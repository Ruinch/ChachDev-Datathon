# Разметка восьми спорных видео

Эта очередь нужна для поиска причин ложных тревог и пропусков. После настройки на этих роликах они становятся материалом разработки, а не независимым экзаменом модели. Банковские материалы и JSON разметки остаются на ноутбуке.

Уточнение владельца от 18.10.2026: двоичные метки в основном Excel даны
организаторами, а текстовые заметки добавлены владельцем и имеют приоритет перед
разбором ИИ. Временные точки — приблизительные ориентиры, иногда начало, иногда
момент внутри события. Их нельзя считать точными границами или эталоном ошибки
локализации. Все восемь уже имеют двоичную метку; четыре отрицательных дополнительно
подтверждены владельцем. Повторная полная разметка всех восьми не является условием
продолжения разработки. Существующих меток достаточно для оценки совпадения с
организаторами, заметок — для разбора гипотез. Приведённая ниже полная процедура
нужна, когда требуется уточнить конкретное спорное событие или подготовить эталон
типов, интервалов и полноты проверки. Машинные гипотезы не заменяют такой эталон.

## Открытие и повторный запуск

Сейчас подготовлена приватная очередь `.local_ml/review-eight-human-v1/queue.json`. Она содержит восемь уникальных видео, исходные человеческие заметки и пустые списки подтверждённых событий. Машинные гипотезы в неё не включены. Старая очередь `.local_ml/review-temporal-v12` и прежний ручной экспорт сохранены.

Из корня проекта:

```powershell
.\.venv\Scripts\python -m ml_tools.review_server --queue .local_ml\review-eight-human-v1\queue.json --port 8766
```

Откройте `http://127.0.0.1:8766/`. Manifest, видео и человеческие черновики загружаются автоматически. Восемь записей доступны в выпадающем списке. Сервер слушает только loopback и отдаёт только выбранные видео; его нельзя включать в Funnel.

Режим `ml_tools/review.html` через `file://` также работает: в нём Manifest и MOV выбираются вручную. Рабочий кабинет на порту 8000 и этот разметчик — отдельные страницы.

## Первый проход: весь ролик без постановки диагноза

1. Просмотрите видео целиком без звука. Не начинайте с предполагаемой ошибки модели.
2. В поле **Ракурс и видимость** запишите, по каким наблюдаемым действиям определены кассир и клиент: работа за служебным оборудованием, получение денег через зону передачи, выполнение кассовой операции. Положение слева или справа само по себе не определяет роль.
3. Укажите вид операции: подтверждённый приём денег от клиента, выдача клиенту, внутренний пересчёт либо неизвестно. Отметьте, видна ли исходная передача именно этих банкнот. Если нет — не угадывайте владельца денег.
4. В поле **Неоднозначность и ограничения** перечислите перекрытия, выход людей или денег из кадра, невидимый экран, обрыв начала или конца операции, монтаж.
5. Определите **Группу исходной съёмки / смены / камеры**. У связанных фрагментов одной съёмки должна быть одна группа. Разные ракурсы не доказывают разные сессии. Не назначайте отдельную группу каждому файлу только ради заполнения. Если происхождение неизвестно, оставьте поле пустым и сохраняйте черновик без галочки полного просмотра.

## Второй проход: каждое видимое событие отдельно

У каждого события нужны тип, начало, конец и наблюдаемое описание. Одна запись события — один непрерывный эпизод. Не создавайте новое событие для каждого похожего кадра. Повтор после завершения первого эпизода отметьте отдельно. Для одних и тех же денег при новом клиенте используйте R20-B, не дублируйте это же событие как R20-C.

Все времена берутся из исходного ролика, который показывает плеер. Не вычитайте начало фрагмента и не переносите цифры из разборов ИИ.

| Время | Что отметить |
| --- | --- |
| `start_sec` — поле **Начало** | Первая точка, где уже одновременно видны условия предполагаемого события. Нажмите **Начало события** на нужном кадре. |
| `peak_sec` — точка доказательства | Самый ясный момент внутри события для доказательного кадра; это не обязательно середина. Сейчас отдельного поля нет: запишите `peak_sec=…` в описание. |
| `end_sec` — поле **Конец** | Последняя видимая точка того же непрерывного эпизода. Остановите плеер и нажмите **Конец события**. Если видео обрывается раньше окончания, прямо напишите это. |
| `context_start_sec` / `context_end_sec` | Более широкий интервал, позволяющий установить передачу денег, роли, границу операции и последующее действие. Он может охватывать весь ролик. Запишите эти две точки в описание; не растягивайте ради контекста сам интервал нарушения. |

Шаблон описания для каждого события:

```text
Кто действует и почему это кассир/клиент: …
Вид операции и видимая передача конкретных денег: …
Действие, которое непосредственно видно: …
Что подтверждает границу операции / появление следующего клиента: …
peak_sec=…; context_start_sec=…; context_end_sec=…
Что не видно и какие альтернативные объяснения остаются: …
```

Время `peak` должно лежать между `start` и `end`. Контекст должен включать событие. Когда точную границу установить нельзя, не придавайте ей ложную точность: укажите ближайшие видимые границы и причину неопределённости в тексте.

## Как выбирать исследуемый класс

- **R20-A:** видно принятие или пересчёт конкретных клиентских денег, а соответствующий клиент явно отсутствует у места обслуживания. Уход другого человека не подходит. Невидимая клиентская зона — недостаточный контекст.
- **R20-B:** прослеживаются деньги предыдущего клиента, и есть видимые признаки начала обслуживания следующего. Просто второй человек в кадре не подтверждает новую операцию.
- **R20-C:** прослеживаются ранее принятые клиентские деньги, видимо завершение операции и последующее действие, подтверждающее окончание обработки; деньги остаются вне места хранения. Пауза, бумаги на столе и движение к сейфу не подтверждают этот сценарий сами по себе.
- **R22:** сначала должен быть подтверждён **приём наличных от клиента**, затем уход именно кассира до завершения этого приёма. Выдача денег, внутренний пересчёт и неизвестный вид операции не относятся к этому классу автоматически.
- **OTHER:** наблюдение видно, но к перечисленным классам не подходит. Опишите его, не подбирайте нормативный пункт наугад.

Это разметка наблюдений для проверки модели. Выбор класса ещё не подтверждает юридическое нарушение. Отсутствие передачи бумажного удостоверения не доказывает отсутствие идентификации через банковскую систему.

## Итог для каждого ролика

- **Наблюдаемое событие:** добавлено хотя бы одно подтверждаемое по видео событие.
- **Событий проверяемых типов не видно:** весь ролик просмотрен, событий этих типов не найдено, а список событий пуст. Это не утверждение о соблюдении всех банковских требований.
- **Неясно:** видимость или контекст не позволяют надёжно выбрать вывод. Укажите причину. Если часть событий доказана, а другие процедуры не проверить, сохраните доказанные события и перечислите ограничения; при невозможности общего вывода допустим итог «Неясно» с этими событиями.

Галочка **Весь ролик просмотрен, все события записаны** сохраняется в JSON как `reviewed=true`. Она требует проверенной группы съёмки. Не ставьте её после просмотра только спорной точки. Если группа пока неизвестна, сохраните всё как черновик и укажите, что видео просмотрено, но группа не установлена.

`exhaustive=true` — отдельное требование будущего обучающего набора: человек проверил **все перечисленные процедуры во всём заданном окне**, включая отсутствие дополнительных событий. В текущем просмотрщике отдельного поля `exhaustive` нет; JSON для обучения автоматически из этой галочки не создаётся. В заметках полезно явно перечислить проверенные R20-A/B/C/R22 и процедуры, для которых контекста недостаточно.

## Сохранение — после каждого ролика

1. Нажмите **Сохранить запись в память страницы**.
2. Нажмите **Скачать разметку JSON**. Кнопка сохранения сама по себе не записывает файл на диск.
3. Сохраните свежую версию как `.local_ml/review-eight-human-v1/annotations-human.json`; при промежуточных копиях сохраните предыдущую версию отдельно.
4. При перезагрузке страницы сначала автоматически появятся исходные черновики. Загрузите **последний скачанный JSON** через **Продолжить разметку**. Он заменяет разметку в памяти страницы — перед импортом другой версии экспортируйте текущую.

Проверка сохранённой структуры, без вывода содержимого:

```powershell
.\.venv\Scripts\python -m ml_tools.annotations .local_ml\review-eight-human-v1\annotations-human.json --manifest .local_ml\review-temporal-v12\dataset.json
```

Не используйте `--finalize-groups` после разметки только этих восьми видео: для итогового независимого деления нужна проверка групп всего набора. Новый человеческий JSON будет использован локально для разбора FP/FN, затем потребуется повторная оценка на целых независимых группах.
