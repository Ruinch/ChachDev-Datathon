# Локальная проверка кассовых процедур по видео

Проект для кейса ForteBank на Datathon 26. Цель — принять запись `.mov`, найти визуально подтверждаемые эпизоды, показать таймкод и 1–3 настоящих кадра из исходного видео и связать наблюдение с проверенным нормативным пунктом РК. Вывод служит подсказкой проверяющему человеку.

## Состояние проекта

Сейчас работает **каркас**, а распознавание событий ещё не подключено. Интерфейс, загрузка, API-ключ, локальное хранение задач и статусы готовы. После загрузки задача честно переходит в `failed` с кодом `analyzer_unavailable`. До подключения и проверки локальной модели сервис не выдаёт `no_violation` и не является готовым решением для жюри.

Изученное ТЗ требует результат за 5 минут, полностью локальную обработку без облачных AI-сервисов, несколько нарушений в одном видео и JSON со статусами `processing`, `done`, `failed`. Кадры в ответе API должны быть JPEG в base64. Анализ звука и идентификация лиц запрещены. Архив датасета и его видео не следует добавлять в репозиторий или публиковать.

Локальный архив организаторов содержит 42 `.mov` и таблицу с 42 строками: 22 помечены как нарушение, 20 — как отсутствие нарушения. Для положительного ролика есть только одна временная точка, без типа и интервала. Ролики длятся от 11,63 до 142,53 секунды. Есть две пары побайтовых дубликатов; у одной положительной пары одинаковое видео имеет разные отметки 57 и 68 секунд. Разметку этой пары нужно уточнить локальным просмотром, прежде чем использовать её для оценки. Кадры здесь не просматривались через облачный AI.

## Быстрый локальный запуск

Нужен Python 3.11+ и установленный для него `pip`. В PowerShell из корня проекта:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python -m pip install -e ".[test]"
$env:APP_API_KEY = "вставьте-длинный-случайный-ключ"
.\.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`. Введите тот же ключ в форме. Данные задач сохраняются в `.local_data/` и игнорируются Git. Для извлечения доказательных кадров после подключения модели потребуется локальный FFmpeg; путь к нему можно передать в `APP_FFMPEG_BIN`.

Настройки: `APP_API_KEY` обязателен; `APP_DATA_DIR` задаёт каталог задач вне исходников; `APP_MAX_UPLOAD_MB` задаёт лимит файла (по умолчанию 128 МБ). Для проверки каркаса:

```powershell
.\.venv\Scripts\python -m pytest -q
```

## Контракт API

`POST /api/v1/analyze` принимает multipart поле `file` с `.mov` и заголовок `X-API-Key`. Возвращает HTTP 202 и `{"job_id":"...","status":"processing"}`. `GET /api/v1/jobs/{job_id}` с тем же заголовком возвращает статус задачи. Пример успешного ответа по схеме ТЗ:

```json
{
  "job_id": "3f2a9c1e-0e97-4a27-bfe2-53f61248b324",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Наблюдаемый тип события",
      "timecode_sec": 44.2,
      "description": "Что видно в записи и почему это требует проверки",
      "evidence_frames": [
        { "timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..." }
      ],
      "rule": {
        "title": "Правила ведения кассовых операций",
        "clause": "пункт 20",
        "source_url": "https://old.adilet.zan.kz/rus/docs/V1900019680"
      }
    }
  ]
}
```

`rule` — дополнительное поле для нормативной ссылки, требуемой пользовательским сценарием. При `no_violation` массив `violations` пуст. Техническая ошибка возвращается со статусом `failed` и полем `error`, без фиктивного вердикта. Кадры должен извлекать сервер из исходного файла по вычисленным таймкодам; модель не создаёт их и не пишет произвольные ссылки на нормы.

## Устройство

```text
frontend/       форма загрузки, ход обработки и карточки событий
app/main.py     HTTP API и запуск фоновой задачи
app/storage.py  SQLite и локальные файлы задач
app/analyzer.py интерфейс для будущего локального анализатора
app/evidence.py извлечение JPEG из исходного видео через FFmpeg
app/schemas.py  схема ответа жюри и нормативные ссылки
docs/           кандидаты правил и протокол выбора модели
tests/          проверки API-контракта и отказов
```

На этой стадии сервер запускается в **одном процессе**. Фоновая задача FastAPI подходит для каркаса; перед публичной проверкой нужно измерить очередь и устойчивость при нескольких загрузках. Прерванные при рестарте задачи помечаются `failed`.

## Следующие этапы

| Этап | Работа | Условие перехода |
| --- | --- | --- |
| 1. Локальный просмотр данных | Состав архива, метки и длительности проверены. Дальше вручную описать видимые действия, границы операций и спорную пару дубликатов; выделить отложенные целые видео. | Есть 2–3 доказуемых кандидата, согласованные метки и независимая проверочная часть. |
| 2. Декодер и замер модели | Установить FFmpeg и совместимую локальную среду, проверить небольшую видеомодель на коротком и самом длинном ролике. | Известны время полного прохода, память и первые ошибки качества. |
| 3. Анализатор событий | Реализовать окна с исходными таймкодами, уточнение эпизодов, объединение повторов и привязку к каталогу правил. | Автоматический JSON содержит несколько событий и только исходные кадры. |
| 4. Независимая проверка | Измерить пропуски, ложные тревоги, точность времени и правила на отложенных видео и другом ракурсе. | Качество зафиксировано, полный цикл занимает меньше 5 минут с запасом. |
| 5. Публичный запуск | Проверить ключ, URL жюри, параллельные загрузки, перезапуск и работу без исходящего интернета. | Есть работающий публичный интерфейс/API и инструкция для сдачи. |

При команде из трёх человек можно работать параллельно: участник **видео и модели** ведёт этапы 1–3; участник **сервиса** доводит API, очередь и развёртывание; участник **правил и проверки** ведёт каталог норм, разметку и независимую оценку. Совместная контрольная точка — первый замер на длинном видео и согласование типов событий до настройки порогов.

Подробности: [кандидатные правила](docs/rules.md) и [протокол выбора модели](docs/model-evaluation.md). Исходное ТЗ — `Кейс_ForteBank.docx` из папки организаторов; оно не включено в репозиторий.
