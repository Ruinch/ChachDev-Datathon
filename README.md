# Кассовый контроль

Сервис для проверки видеозаписей банковских кассовых процедур, разработанный для кейса ForteBank на Datathon 26. Принимает `.mov`, выделяет эпизоды для проверки и показывает их время, исходные кадры и нормативный источник РК.

Результат помогает проверяющему изучить запись. Модель может ошибаться; окончательный вывод требует просмотра видео и проверки условий применимой нормы.

[Состояние проекта](docs/project-status.md) · [Запуск на втором ноутбуке](docs/second-laptop.md) · [Настройки и развёртывание](docs/deployment.md) · [Дообучение](docs/finetuning.md)

## Текущее состояние

- **Сайт и API реализованы:** загрузка записи, журнал, статусы, просмотр оригинала, карточки событий, экспорт JSON и печать отчёта.
- **Локальная модель подключена экспериментально:** Qwen3.5-4B через llama.cpp. Качество распознавания пока не прошло приёмку — есть пропуски и ложные события.
- **Оба поставляемых каталога распознавания отключены.** Сайт можно запустить, но анализ новых видео недоступен до подготовки модели и подключения принятого набора правил. `ready=false` и HTTP 503 в этом состоянии ожидаемы.
- **Подготовка дообучения реализована**, но новых дообученных весов пока нет.

Последние измерения и ограничения оценки: [ML-протокол](docs/ml-native-video.md). Успешные программные тесты подтверждают работу сервиса, но не точность распознавания.

## Возможности

- Приём MOV с проверкой формата, размера и длительности.
- Автоматическая обработка принятой задачи и сохранение результата в журнале.
- Несколько событий в одной записи: тип, таймкод, наблюдение, 1–3 JPEG и ссылка на правило.
- Просмотр исходного видео с переходом к событию и увеличение доказательных кадров.
- Отображение неполного анализа и недостатка визуального контекста.
- Правовая справка: порядок действий, необходимые условия, исключения и официальные источники.
- Защищённый API, экспорт JSON и печать средствами браузера.

Кадры извлекаются из исходного файла; ссылки на нормы подставляются из каталога правил. Модель возвращает наблюдение и идентификатор процедуры. Наличие правовой справки само по себе не включает распознавание.

## Требования

Проверенные запускатели рассчитаны на **Windows и Python 3.12–3.13**.

| Компонент | Для чего нужен |
| --- | --- |
| Python с Python Launcher (`py`) | Создание среды и запуск сервиса. Для целевого ноутбука выбран Python 3.12. |
| FFmpeg и FFprobe | Проверка видео и извлечение кадров. Устанавливаются отдельно. |
| NVIDIA GPU и совместимый драйвер | Запуск локальной модели. Инференс выбранной конфигурации измерялся на RTX 4050 Laptop 6 ГБ / RAM 16 ГБ. |
| Node.js 22+ | Только тесты интерфейса; для работы сайта не требуется. |

Для просмотра сайта GPU и веса не нужны. Возможность инференса на 6 ГБ не означает возможность обучения той же модели; требования к обучению описаны [отдельно](docs/finetuning.md).

## Быстрый запуск сайта и API

Откройте PowerShell в корне проекта. FFmpeg и FFprobe должны быть в `PATH` либо в `.local_tools/ffmpeg/bin/`.

```powershell
.\scripts\setup.ps1 -PythonVersion 3.12
.\scripts\start.ps1
```

Подготовка создаёт отсутствующую `.venv`, устанавливает закреплённые зависимости и создаёт отсутствующий `.env` со случайным ключом. Существующая совместимая среда и конфигурация сохраняются. Модели и медиоинструменты этот скрипт не скачивает.

1. Откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
2. Найдите `APP_API_KEY` в локальном `.env`.
3. Введите его в разделе **«Подключение»** и проверьте состояние сервиса.

Если FFmpeg/FFprobe ещё не установлены, для просмотра интерфейса используйте:

```powershell
.\scripts\setup.ps1 -PythonVersion 3.12 -AllowMissingMediaTools
.\scripts\start.ps1 -AllowMissingMediaTools
```

Анализ при этом недоступен. Остановить сервер можно сочетанием `Ctrl+C`. Если PowerShell блокирует выполнение скрипта, его можно вызвать через `powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1`.

## Запуск вместе с локальной моделью

На целевом ноутбуке сайт, API и модель работают на одной машине. Остановите ранее запущенный сайт, чтобы освободить порт 8000. После установки Python, драйвера NVIDIA и медиоинструментов выполните:

```powershell
.\scripts\setup.ps1 -IncludeML -PythonVersion 3.12
.\.venv\Scripts\python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json
.\scripts\start-ml.ps1 -CheckOnly
.\scripts\start-ml.ps1
```

Установщик скачивает публичные веса Qwen3.5-4B Q4_K_M, проектор и runtime, закреплённые в lock-файле, и проверяет SHA-256. Датасет ему не нужен. Для проверки уже перенесённых файлов без скачивания:

```powershell
.\.venv\Scripts\python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json --verify-only
```

`start-ml.ps1` запускает модель на `127.0.0.1:8091` и сайт на `127.0.0.1:8000`. Он не включает правила. `-CheckOnly` проверяет подготовленные файлы и среду без запуска серверов; это не проверка качества модели. Уже работающий runtime можно использовать только с явным `-UseExistingModel` после сверки его параметров.

**Отключённый каталог по-прежнему блокирует анализ.** После приёмки качества подключается принятый каталог и выполняется строгая проверка готовности. Порядок настройки, переноса файлов и полного запуска: [инструкция для второго ноутбука](docs/second-laptop.md). Текущий адаптер рассчитан на llama.cpp; Ollama не является готовой заменой этого подключения.

## Как пользоваться

1. **Подключение:** введите ключ и проверьте готовность модели, медиоинструментов и правил.
2. **Новая проверка:** выберите MOV и запустите анализ, когда сервис готов.
3. **Разбор записи:** изучите события, перейдите к их времени, рассмотрите кадры и нормативный источник.
4. **Журнал проверок:** найдите сохранённую задачу, откройте результат или вернитесь к нему по ссылке `/?job=UUID`.
5. **Процедуры:** сверьте условия правила, исключения и редакцию источника.

Ключ хранится в памяти страницы; после её обновления его нужно ввести заново. Сама задача и результат сохраняются на сервере.

| Исход проверки | Что он означает |
| --- | --- |
| Эпизоды для проверки | Найдены наблюдения, требующие сверки человеком. При частичном анализе отдельно показаны ограничения. |
| События не найдены | Полная проверка не выявила событий среди включённых процедур. Это не гарантия отсутствия любых нарушений. |
| Недостаточно данных для вывода | Нужные условия не удалось оценить; нарушение не подтверждено и не исключено. |
| Проверка не завершена | Технический сбой или прерывание обработки. |

## API

Все маршруты `/api/v1/` требуют заголовок `X-API-Key`. Интерактивная документация: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs). Для запросов в Swagger введите ключ через **Authorize**.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/system` | Готовность, лимиты и занятость сервиса. |
| `POST /api/v1/analyze` | Загрузка MOV: multipart-поле `file`. При принятии — HTTP 202, `job_id` и `status="processing"`. |
| `GET /api/v1/jobs/{job_id}` | Статус задачи, результат или причина отказа. |
| `GET /api/v1/jobs` | Журнал с поиском, фильтрами и страницами. |
| `GET /api/v1/jobs/{job_id}/video` | Защищённый оригинал видео с поддержкой Range. |
| `GET /api/v1/rules` | Каталог распознавания и состояние его правил. |
| `GET /api/v1/legal-guide` | Правовая справка. |

Статусы задач: `processing`, `done`, `failed`. У завершённой проверки `verdict` равен `violation` или `no_violation`; ответ включает `violations`, охват `analysis_scope` и метаданные. JPEG передаются в base64. Недостаток контекста без подтверждённых событий возвращается как `failed / insufficient_evidence`, без выдуманного вердикта.

До создания задачи возможны HTTP 401 (ключ), 503 (неготовность), 429 (занятость), 408 (время загрузки), 413 (размер/длительность) и 422 (непригодный файл). При потере ответа на загрузку сначала проверьте журнал: повторный POST может создать вторую задачу. Подробный контракт анализатора: [ML-интеграция](docs/ml-integration.md).

## Проверка установки

```powershell
# Среда, Python/API, интерфейс и запускатели; нужен Node.js 22+:
.\scripts\check.ps1 -RunTests

# Проверка работающего API в другом окне PowerShell:
.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000

# После подключения принятой модели и активного каталога:
.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RequireAnalyzer
```

Для проверки без FFmpeg/FFprobe добавьте к `check.ps1 -RunTests` флаг `-AllowMissingMediaTools`: соответствующие медиоинтеграции будут пропущены. Необязательные ML-тесты требуют соответствующих пакетов. Установка ML-клиента доступна через `setup.ps1 -IncludeML`, дополнительные проверки групп ракурсов требуют `.[ml-review]`. Состав окружения и результаты последнего полного прогона сохранены в [приёмке](docs/acceptance.md).

Проверки сервиса используют синтетические видео. Качество распознавания, полный результат за пять минут, автономность обработки и публичный доступ проверяются отдельно на машине сдачи.

## Архитектура и данные

Стек: Python, FastAPI, SQLite, обычные HTML/CSS/JavaScript, FFmpeg/FFprobe, PyAV и локальный Qwen3.5 через llama.cpp.

```text
frontend/             кабинет, журнал, видеоплеер и результаты
app/                  API, задачи, хранение и извлечение доказательств
  ml/                 подготовка кадров и клиент локальной модели
  data/               каталоги правил и правовая справка
ml_tools/             установка runtime, оценка и подготовка обучения
scripts/              запуск и проверка Windows-среды
tests/                проверки сервиса, ML-контракта и интерфейса
docs/                 инструкции, архитектура, источники и протоколы
```

Данные задач хранятся в `.local_data/`, веса и локальные ML-материалы — в `.local_ml/`. Эти каталоги и `.env` исключены из Git. Банковские видео, кадры, разметка, описания отдельных записей и ключи не публикуются и не передаются облачным AI. Анализатор не использует звук и не устанавливает личности людей.

Настройки берутся из `.env`; переменные текущего процесса имеют приоритет. Основные параметры и значения по умолчанию приведены в [.env.example](.env.example), полный список — в [развёртывании](docs/deployment.md). Обучение выполняется в отдельной среде, чтобы не менять зависимости работающего сервиса.

## Эксплуатация и публичный доступ

- По умолчанию: MOV до **128 МиБ**, длительность до **180 секунд**.
- Один процесс API и один анализ одновременно. Очереди нет; второй анализ получает HTTP 429.
- Один общий ключ открывает все задачи. Аккаунтов и разграничения по пользователям нет.
- Задачи сохраняются на диске; автоматические очистка и резервное копирование не реализованы. Прерванные при рестарте задачи получают `failed`.
- Обработка моделью выполняется локально после подготовки файлов. Полную работу без исходящего интернета нужно подтвердить на машине сдачи.

Для жюри нужен публичный **HTTPS-адрес сайта и API**. Прокси или туннель направляется на порт 8000; порт модели 8091 не публикуется. Установка проекта не создаёт публичный адрес. Полный цикл, сохранение заголовков `X-API-Key`/`Range` и доступ из другой сети проверяются по [инструкции развёртывания](docs/deployment.md).
