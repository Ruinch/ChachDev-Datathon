# Локальный запуск и подготовка развёртывания

Пока локальная модель и проверенные правила не подключены, можно проверить сайт, API, защиту и хранение. Готовность для жюри подтверждается только реальным анализом видео и замером времени.

## Настройки

Скрипты `scripts/start.ps1` и `scripts/check.ps1` читают `.env` из корня проекта. Они используют `.venv\Scripts\python.exe`; существующие переменные окружения имеют приоритет. Формат `.env` — строки `NAME=value`, необязательные одинарные/двойные кавычки и отдельные строки комментариев `#`. Подстановки `${...}`, команды и комментарии после значения не поддерживаются.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_API_KEY` | нет | Обязательный собственный секрет для всех `/api/v1/` запросов. |
| `APP_DATA_DIR` | `.local_data` | SQLite, исходные записи и кадры. Для развёртывания используйте постоянный каталог на диске вне исходников. |
| `APP_MAX_UPLOAD_MB` | `128` | Максимальный размер файла в МиБ. |
| `APP_MAX_VIDEO_SECONDS` | `180` | Максимальная длительность записи. |
| `APP_UPLOAD_TIMEOUT_SECONDS` | `30` | Общий предел приёма тела запроса загрузки; медленная загрузка прерывается с HTTP 408. |
| `APP_ANALYSIS_TIMEOUT_SECONDS` | `240` | Время принятой задачи, включая старт модели и извлечение кадров. Допустимо положительное значение до 270 с; загрузка и проверка контейнера также занимают время. |
| `APP_FFPROBE_TIMEOUT_SECONDS` | `15` | Предел времени проверки медиаконтейнера. |
| `APP_FFMPEG_BIN` | `ffmpeg` | Исполняемый файл FFmpeg. |
| `APP_FFPROBE_BIN` | `ffprobe` | Исполняемый файл FFprobe. |
| `APP_ANALYZER_FACTORY` | пусто | `module:factory` локального адаптера человека 2. Фабрика вызывается без аргументов внутри процесса задачи. |
| `APP_RULE_CATALOG_PATH` | встроенный каталог | Путь к JSON с проверенными правилами. Поставляемые кандидаты отключены до проверки применимости. |

Сумма `APP_UPLOAD_TIMEOUT_SECONDS + APP_FFPROBE_TIMEOUT_SECONDS + APP_ANALYSIS_TIMEOUT_SECONDS` не может превышать 295 секунд. По умолчанию это 285 секунд; оставшийся запас нужен для ответа и получения результата клиентом. Эти пределы ограничивают зависания, а прохождение пяти минут подтверждается полным измерением на машине сдачи. `scripts/check.ps1` проверяет этот бюджет через настройки приложения до запуска.

Установка `pip install -c constraints.txt -e ".[test]"` из README закрепляет зависимости сервиса и тестов, проверенные на Python 3.13 / Windows. Этот файл не фиксирует пакеты инференса, CUDA и веса; их устанавливают отдельно по инструкции человека 2, совместимо с выбранным Python и оборудованием. После изменения среды моделями повторите проверки сервиса. Для другой ОС/версии Python совместимость закреплённых пакетов ещё нужно подтвердить.

Медиоинструменты должны быть доступны служебной учётной записи, запускающей сервер. Не используйте доступность команды в личном терминале как единственную проверку. Можно хранить локальные исполняемые файлы в игнорируемом каталоге `.local_tools/ffmpeg/bin/` и указать в `.env` абсолютные пути к `ffmpeg.exe` и `ffprobe.exe`; общесистемный `PATH` тогда не нужен. Эти бинарные файлы в репозиторий не включаются.

## Проверка на локальной машине

1. Создайте `.venv`, установите проект и заполните `.env` по README. Не перезаписывайте существующий `.env` командой копирования.
2. Установите FFmpeg и FFprobe и укажите пути. Запустите `.\scripts\check.ps1 -RunTests`.
3. Запустите `.\scripts\start.ps1`. Для просмотра интерфейса без медиоинструментов допустим `-AllowMissingMediaTools`; анализ останется недоступен.
4. После интеграции модели и проверенных правил выполните `.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RequireAnalyzer`. Требуется `ready=true`, а не только доступная главная страница.
5. Пройдите [приёмку](acceptance.md) на настоящих локальных видео.

Отдельный запуск интеграционных проверок с локальными медиоинструментами:

```powershell
$env:APP_FFMPEG_BIN = (Resolve-Path .local_tools\ffmpeg\bin\ffmpeg.exe).Path
$env:APP_FFPROBE_BIN = (Resolve-Path .local_tools\ffmpeg\bin\ffprobe.exe).Path
.\.venv\Scripts\python -m pytest tests/test_pipeline_integration.py -q
```

Если файлы установлены в другом месте, подставьте их полные пути. Прямой запуск `pytest` не читает `.env` автоматически. Проверки создают синтетическое видео и тестовый адаптер: они подтверждают декодирование, исходные кадры и сервисный контракт, а качество распознавания проверяется отдельно на отложенных роликах. При отсутствии FFmpeg/FFprobe интеграционные проверки отмечаются как пропущенные; это не успешная проверка медиаконвейера.

Пример ручной проверки из PowerShell с уже заданным в окружении ключом:

```powershell
$headers = @{ 'X-API-Key' = $env:APP_API_KEY }
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/system -Headers $headers
curl.exe -i -H "X-API-Key: $env:APP_API_KEY" -F "file=@C:\videos\sample.mov" http://127.0.0.1:8000/api/v1/analyze
# Подставьте job_id из HTTP 202:
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/jobs/JOB_ID -Headers $headers
```

Вызов `uvicorn` напрямую не читает `.env` автоматически: используйте скрипт запуска либо заранее экспортируйте настройки. Не передавайте ключ в адресной строке и не вставляйте реальное значение в команды, документацию или снимки экрана для сдачи.

## Публичный адрес после интеграции ML

1. Выберите машину, на которой проверена модель, хватает памяти и есть постоянный диск. Этот проект пока не подтверждает поддержку конкретного GPU или контейнерного рантайма.
2. Храните `APP_DATA_DIR`, каталог правил и веса в постоянных локальных каталогах. Доступ на чтение исходных записей и запись результатов нужен только учётной записи сервиса. Следите за свободным местом: автоматическая очистка и срок хранения пока не настроены.
3. Запускайте **один процесс Uvicorn и один экземпляр приложения** для данного каталога данных. Сервер удерживает блокировку `.server.lock` в каталоге данных; второй процесс с тем же каталогом завершится при старте. Не используйте `--reload` при проверке жюри.
4. Поставьте перед сервером HTTPS reverse proxy на том же домене для `/`, `/static/` и `/api/v1/`. Локальный API может слушать `127.0.0.1:8000`. Согласуйте максимальный размер тела запроса с `APP_MAX_UPLOAD_MB` плюс запас на multipart и время загрузки. Клиенты опрашивают задачу, поэтому держать POST открытым на всё время анализа не нужно.
5. Настройте запуск процесса после перезагрузки и восстановление при падении средствами выбранной машины. Отключите сон. Перезапуск должен сохранять каталог данных, а незавершённая задача — переходить в `failed`.
6. С другой сети проверьте HTTPS, загрузку `.mov`, статус и защищённый видеоплеер. Проверьте, что запросы без ключа отвергаются, а видео и каталог данных не раздаются как статические файлы.
7. Передайте жюри адрес интерфейса, базовый адрес API, отдельный ключ и краткую инструкцию. Публикуйте адрес только после реального полного прогона, завершившегося менее чем за пять минут.

Публикация и изменения GitHub выполняются владельцем проекта. Здесь не настроен действующий публичный адрес.

## Работа без исходящего интернета

Заранее скачайте все Python-пакеты, веса, токенизаторы и конфигурации, запустите модель и сохраните версии среды. Для библиотек Hugging Face после подготовки файлов установите `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`; это дополнение к проверке, а не доказательство автономности произвольного адаптера.

Закройте сервер, отключите исходящий интернет, запустите его заново и выполните полный анализ короткого и самого длинного ролика. Так проверяется и холодный запуск, и отсутствие скрытого скачивания весов. Сайт должен использовать локальные стили/скрипты, кадры и видео — локальные маршруты. Звуковую дорожку, идентификацию лиц и внешние AI-сервисы адаптер не использует.

При публичной проверке входящее соединение жюри должно оставаться доступно; автономность означает отсутствие исходящих обращений анализатора, а не отключение сервера от клиентов.
