# Локальный запуск и подготовка развёртывания

Экспериментальный локальный адаптер добавлен, но приёмка распознавания не пройдена: поставляемые каталоги отключены. Сайт, API, защиту и хранение можно проверять отдельно. Готовность для жюри требует принятого качества, применимых правил и измерения полного времени на машине сдачи. Порядок подготовки ML: [передача анализатора](ml-handoff.md); фактические результаты: [замеры](ml-measurements.md).

Для выбранного второго ноутбука **Windows / RTX 4050 Laptop 6 ГБ / RAM 16 ГБ** подготовлена [пошаговая инструкция переноса, запуска и проверки](second-laptop.md). Сайт, API и модель запускаются на нём; отдельный сервер фронтенда не требуется.

## Настройки

Скрипты `scripts/setup.ps1`, `scripts/start.ps1` и `scripts/check.ps1` работают из любого текущего каталога и читают `.env` из корня проекта. Они используют `.venv\Scripts\python.exe`; существующие переменные окружения имеют приоритет. Относительные пути данных, правил и медиоинструментов разрешаются от корня проекта, включая значения из окружения. Прямой вызов Uvicorn этой нормализации не выполняет.

Для отдельной конфигурации используйте `-EnvPath C:\private\service.env` во всех трёх скриптах. Относительный `-EnvPath` также разрешается от корня проекта. Формат `.env` — строки `NAME=value`, необязательные одинарные/двойные кавычки и отдельные строки комментариев `#`. Подстановки `${...}`, команды и комментарии после значения не поддерживаются.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `APP_API_KEY` | нет | Обязательный собственный секрет для всех `/api/v1/` запросов. |
| `APP_DATA_DIR` | `.local_data` | SQLite, исходные записи и кадры. Для развёртывания используйте постоянный каталог на диске вне исходников. |
| `APP_MAX_UPLOAD_MB` | `128` | Максимальный размер файла в МиБ. |
| `APP_MAX_VIDEO_SECONDS` | `180` | Максимальная длительность записи. |
| `APP_UPLOAD_TIMEOUT_SECONDS` | `30` | Общий предел приёма тела запроса загрузки; медленная загрузка прерывается с HTTP 408. |
| `APP_ANALYSIS_TIMEOUT_SECONDS` | `240` | Время принятой задачи: создание процесса, инициализация адаптера, анализ и извлечение кадров. Если адаптер загружает веса внутри задачи, это время также включено. Допустимо положительное значение до 270 с; загрузка и проверка контейнера также занимают время. |
| `APP_FFPROBE_TIMEOUT_SECONDS` | `15` | Предел времени проверки медиаконтейнера. |
| `APP_FFMPEG_BIN` | `ffmpeg` | Исполняемый файл FFmpeg. |
| `APP_FFPROBE_BIN` | `ffprobe` | Исполняемый файл FFprobe. |
| `APP_ANALYZER_FACTORY` | пусто | `module:factory` локального адаптера. Фабрика вызывается без аргументов внутри процесса задачи. |
| `APP_RULE_CATALOG_PATH` | встроенный каталог | Путь к JSON с проверенными правилами. Поставляемые кандидаты отключены до проверки применимости. |

Сумма `APP_UPLOAD_TIMEOUT_SECONDS + APP_FFPROBE_TIMEOUT_SECONDS + APP_ANALYSIS_TIMEOUT_SECONDS` не может превышать 295 секунд. По умолчанию это 285 секунд; оставшийся запас нужен для ответа и получения результата клиентом. Эти пределы ограничивают зависания, а прохождение пяти минут подтверждается полным измерением на машине сдачи. `scripts/check.ps1` проверяет этот бюджет через настройки приложения до запуска.

Скрипт подготовки создаёт отсутствующую `.venv` через установленный Python Launcher `py -3.13` и устанавливает `pip install -c constraints.txt -e ".[test]"`. Для новой среды Python 3.12 задайте `-PythonVersion 3.12`; для установки закреплённых зависимостей локального ML-клиента добавьте `-IncludeML` (эквивалент `.[ml,test]`). Скрипты принимают Python 3.12–3.13 и проверяют точное совпадение установленных сервисных версий с `constraints.txt`; существующая ML-среда Python 3.12 сохраняется, неподходящая `.venv` не пересоздаётся автоматически. Runtime CUDA и веса устанавливаются отдельно по lock-файлу. После изменения среды повторите проверки. Для другой ОС/версии Python нужен ручной запуск и отдельное подтверждение совместимости.

`scripts/start-ml.ps1` поднимает встроенный runtime Qwen3.5-4B и API. Он не скачивает файлы, не включает правила и не принимает доступность модели за качество. По умолчанию интерфейс запускается и с отключённым каталогом, но анализ остаётся недоступен. `-RequireAnalyzer` требует принятый каталог до запуска; после старта дополнительно нужен live-check с `-BaseUrl`. `-CheckOnly` проверяет локальные предпосылки, не создавая серверы. Уже работающий runtime автоматически не используется: `-UseExistingModel` задаётся явно после сверки его весов и параметров. Остановка объединённого запуска завершает только созданный им runtime.

Перед стартом `ml_tools/start_model.ps1` проверяет веса, сохранённые публичные архивы и извлечённые бинарные файлы по выбранному lock. Это проверка локальных файлов, а не идентификация чужого процесса на порту. Для переноса сохраняйте также `.local_ml/downloads/`. Отдельная команда `python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json --verify-only` ничего не скачивает и не меняет. Обычный установщик по умолчанию использует этот же lock Qwen3.5-4B; неизвестные/повреждённые существующие веса не заменяются автоматически.

Адаптер `app.local_analyzer:build_analyzer` создаёт в каждой задаче клиент к отдельному llama.cpp на loopback. Веса остаются в процессе runtime между заданиями; этот процесс запускается заранее, а его холодный старт измеряется отдельно. В замер полного запуска включаются и готовность runtime, и путь от загрузки MOV до получения результата. API по-прежнему обрабатывает только одну задачу и отвечает HTTP 429 на конкурентный анализ: очереди ожидания нет. Числа из [ML-замеров](ml-measurements.md) получены на другой машине с RTX 4050 Laptop 6 ГБ и не подтверждают скорость текущего компьютера с GTX 1650 Ti 4 ГБ.

Для встроенного адаптера `GET /api/v1/system` отдельно показывает `analyzer.runtime`: установлены ли зависимости PyAV, допустим ли `APP_LOCAL_MODEL_URL` и отвечает ли `/health` модели. HTTP-проверка ждёт не более 0,75 секунды, обращается только на literal loopback без proxy и редиректов и не загружает веса. Перед приёмом POST она выполняется заново: недоступный runtime даёт HTTP 503 без создания задачи и сохранения файла. Поле видно даже с отключёнными правилами; `ready=true` требует также готовых инструментов и принятого каталога. Ответ `/health` не подтверждает версию весов или качество — сверьте их отдельно. Для других фабрик `analyzer.runtime=null`: их доступность эта проба не проверяет.

Медиоинструменты должны быть доступны служебной учётной записи, запускающей сервер. Для стандартных имён `ffmpeg`/`ffprobe` скрипты автоматически подхватывают `.local_tools/ffmpeg/bin/ffmpeg.exe` и `ffprobe.exe`, если они есть; иначе используют `PATH`. Можно задать собственные пути в `.env`. Эти бинарные файлы в репозиторий не включаются; `setup.ps1` их не скачивает и не меняет системный `PATH`.

## Проверка на локальной машине

1. Для создания новой среды установите Python 3.12 или 3.13 с Python Launcher. Выполните `.\scripts\setup.ps1` (для 3.12 — с `-PythonVersion 3.12`): создаются отсутствующие `.venv` и `.env`, устанавливаются закреплённые зависимости сервиса. Новый ключ генерируется криптографическим генератором и сохраняется в `.env` без вывода в терминал. Если `APP_API_KEY` уже задан в окружении, для нового файла используется он. Существующий `.env` сохраняется побайтово; если в нём пустой ключ, задайте значение самостоятельно. `-IncludeML` устанавливает ML-клиент, но модель, CUDA и веса не устанавливаются.
2. Установите FFmpeg и FFprobe локально. Повторите `.\scripts\setup.ps1 -SkipInstall`: эта команда не создаёт среду и не устанавливает пакеты, а проверяет уже установленную. Для временного просмотра интерфейса без медиоинструментов добавьте `-AllowMissingMediaTools`. Откройте локальный `.env` и используйте его ключ для подключения в интерфейсе.
3. Запустите `.\scripts\start.ps1`. Для просмотра интерфейса без медиоинструментов допустим `-AllowMissingMediaTools`; анализ останется недоступен.
4. После интеграции модели и проверенных правил выполните `.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RequireAnalyzer`. Требуется `ready=true`, а не только доступная главная страница.
5. Пройдите [приёмку](acceptance.md) на настоящих локальных видео.

Проверки сервисной части до подключения ML:

```powershell
.\scripts\check.ps1 -RunTests
.\scripts\test-launchers.ps1
```

`-RunTests` включает Python/API, тесты поведения JavaScript-модулей и проверки Windows-скриптов. Для этого режима требуется Node.js 22 или новее, без установки npm-пакетов; обычному start Node.js не нужен. Отдельная вторая команда проверяет повторный setup, отсутствие ключа в выводе, сохранность существующей конфигурации, запуск из другого каталога и разрешение путей. Она использует отдельные временные конфигурации, не меняет проектный `.env` и не обращается в сеть. Отсутствующая модель выдаёт предупреждение и не мешает проверке сервисной части. `-RequireAnalyzer` используйте для приёмки всего решения после интеграции.

Снимок воспроизводимой среды сохраняет `scripts/export-runtime-report.ps1 -VerifyModel`: версии Python/пакетов/GPU, хеши кода, каталога и выбранного lock, а также список разрешённых несекретных ML-настроек. Ключ, пути к банковским данным, разметка и видео не экспортируются. Отчёт сохраняется локально в `.local_data/scratch/`, предыдущий файл не перезаписывается. Это не замер качества; ручные параметры чужого runtime нужно фиксировать отдельно.

Отдельный запуск интеграционных проверок с локальными медиоинструментами:

```powershell
$env:APP_FFMPEG_BIN = (Resolve-Path .local_tools\ffmpeg\bin\ffmpeg.exe).Path
$env:APP_FFPROBE_BIN = (Resolve-Path .local_tools\ffmpeg\bin\ffprobe.exe).Path
.\.venv\Scripts\python -m pytest tests/test_pipeline_integration.py -q
```

Если файлы установлены в другом месте, подставьте их полные пути. При использовании `scripts/check.ps1 -RunTests` пути из `.env` и локальные инструменты подхватываются автоматически. Прямой запуск `pytest` не читает `.env`. Проверки создают синтетическое видео и тестовый адаптер: они подтверждают декодирование, исходные кадры и сервисный контракт, а качество распознавания проверяется отдельно на отложенных роликах. При отсутствии FFmpeg/FFprobe интеграционные проверки отмечаются как пропущенные; это не успешная проверка медиаконвейера.

Пример ручной проверки из PowerShell с уже заданным в окружении ключом:

```powershell
$headers = @{ 'X-API-Key' = $env:APP_API_KEY }
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/system -Headers $headers
curl.exe -i -H "X-API-Key: $env:APP_API_KEY" -F "file=@C:\videos\sample.mov" http://127.0.0.1:8000/api/v1/analyze
# Подставьте job_id из HTTP 202:
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/v1/jobs/JOB_ID -Headers $headers
```

Вызов `uvicorn` напрямую не читает `.env` автоматически: используйте скрипт запуска либо заранее экспортируйте настройки. Не передавайте ключ в адресной строке и не вставляйте реальное значение в команды, документацию или снимки экрана для сдачи.

## Публичный адрес после интеграции ML

1. Выберите машину, на которой проверена модель, хватает памяти и есть постоянный диск. Этот проект пока не подтверждает поддержку конкретного GPU или контейнерного рантайма.
2. Храните `APP_DATA_DIR`, каталог правил и веса в постоянных локальных каталогах. Доступ на чтение исходных записей и запись результатов нужен только учётной записи сервиса. Следите за свободным местом: автоматическая очистка и срок хранения пока не настроены.
3. Запускайте **один процесс Uvicorn и один экземпляр приложения** для данного каталога данных. Сервер удерживает блокировку `.server.lock` в каталоге данных; второй процесс с тем же каталогом завершится при старте. Не используйте `--reload` при проверке жюри.
4. Поставьте перед сервером HTTPS reverse proxy на том же домене для `/`, `/static/` и `/api/v1/`. Локальный API может слушать `127.0.0.1:8000`. Согласуйте максимальный размер тела запроса с `APP_MAX_UPLOAD_MB` плюс запас на multipart и время загрузки. Клиенты опрашивают задачу, поэтому держать POST открытым на всё время анализа не нужно.
5. Настройте запуск процесса после перезагрузки и восстановление при падении средствами выбранной машины. Отключите сон. Перезапуск должен сохранять каталог данных, а незавершённая задача — переходить в `failed`.
6. С другой сети проверьте HTTPS, загрузку `.mov`, статус и защищённый видеоплеер. Проверьте, что запросы без ключа отвергаются, а видео и каталог данных не раздаются как статические файлы.
7. Передайте жюри адрес интерфейса, базовый адрес API, отдельный ключ и краткую инструкцию. Публикуйте адрес только после реального полного прогона, завершившегося менее чем за пять минут.

### Параметры HTTPS-прокси

Прокси должен обслуживать один origin и передавать запросы к локальному `127.0.0.1:8000`, сохраняя `X-API-Key` и `Range`. Маршруты `/docs` и `/openapi.json` также нужны для интерактивной документации; её JavaScript/CSS хранятся локально. Ответы `/api/v1/` и исходные записи не должны попадать в общий кеш. HTTP перенаправляется на HTTPS; сертификат проверяется из внешней сети.

Предел тела загрузки должен быть выше 128 МиБ по умолчанию с запасом не менее 1 МиБ на multipart; при изменении `APP_MAX_UPLOAD_MB` обновите оба ограничения. Таймаут прокси для POST должен покрывать приём файла и его проверку: по умолчанию 30 + 15 секунд с запасом. Анализ продолжается в отдельном процессе после ответа HTTP 202; результат получают опросом GET. Не добавляйте автоматические повторные POST-запросы: при потере ответа сначала проверьте журнал, чтобы не создать повторную проверку.

Настройка конкретного прокси и автозапуска зависит от выбранного хоста и подтверждается на нём. Публичный запуск не выполняет скрипт `setup.ps1`; он подготавливает только локальную среду.

### Данные и восстановление

Один общий ключ даёт доступ ко всем задачам; многопользовательского разграничения нет. Храните `.env`, исходные видео и резервные копии в каталогах с доступом только служебной учётной записи и владельцу. Не копируйте `.env` в публичные материалы. Смена ключа требует перезапуска сервиса и передачи нового ключа проверяющему.

Для согласованной резервной копии остановите сервер и скопируйте весь `APP_DATA_DIR`, включая `jobs.sqlite3` и каталог `jobs/`; это сохраняет связи метаданных с оригиналами и кадрами. Затем запустите сервер снова. Не подменяйте одну базу без файлов задач. Проверяйте восстановление на отдельном каталоге данных; для этого удобно использовать отдельный `-EnvPath` и свободный порт. Срок хранения и очистка остаются административной процедурой: не удаляйте файлы из активной задачи.

Публикация и изменения GitHub выполняются владельцем проекта. Здесь не настроен действующий публичный адрес.

## Работа без исходящего интернета

Заранее скачайте все Python-пакеты, веса, токенизаторы и конфигурации, запустите модель и сохраните версии среды. Для библиотек Hugging Face после подготовки файлов установите `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`; это дополнение к проверке, а не доказательство автономности произвольного адаптера.

Остановите API и принадлежащий вам процесс модели, отключите исходящий интернет, запустите оба заново и выполните полный анализ короткого и самого длинного ролика. Так проверяются холодная загрузка весов и отсутствие скрытого скачивания. Сайт должен использовать локальные стили/скрипты, кадры и видео — локальные маршруты. Звуковую дорожку, идентификацию лиц и внешние AI-сервисы адаптер не использует. Для поставленного адаптера подготовленные локальные файлы и флаг `--offline` описаны в [ML-передаче](ml-handoff.md); сами по себе они не заменяют этот прогон.

При публичной проверке входящее соединение жюри должно оставаться доступно; автономность означает отсутствие исходящих обращений анализатора, а не отключение сервера от клиентов.
