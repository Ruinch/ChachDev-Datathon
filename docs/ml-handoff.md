# Передача локальной ML-части

Реализация `app.local_analyzer:build_analyzer` совместима с актуальным контрактом сервиса. Она получает длительность и включённые `rule_id`, возвращает наблюдения, исходные таймкоды, полноту и ограничения. JPEG и нормативные ссылки создаёт сервис. Показатели качества и готовность к сдаче: [замеры](ml-measurements.md).

## Подготовка

Windows, Python 3.12 или 3.13, NVIDIA GPU. На машине разработки: RTX 4050 Laptop 6 ГБ, 16 ГБ ОЗУ. FFmpeg и FFprobe должны находиться в PATH либо `.local_tools/ffmpeg/bin/`. Скрипт установки сервиса создаёт отсутствующий `.env` со случайным ключом, сохраняя существующий.

```powershell
.\scripts\setup.ps1
.\.venv\Scripts\python -m pip install -c constraints.txt -e ".[ml,test]"
.\.venv\Scripts\python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json
```

Последняя команда один раз скачивает публичные веса и runtime и проверяет SHA-256. `model35-lock.json` закрепляет Qwen3.5-4B Q4_K_M, FP16-проектор, ревизию репозитория и llama.cpp b11669. Исходная модель и конверсия распространяются по Apache-2.0. [Исходная модель](https://huggingface.co/Qwen/Qwen3.5-4B), [поставщик GGUF](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF). Старые lock-файлы сохранены для воспроизводимости сравнений.

Более крупный 9B зафиксирован в `model35-9b-lock.json`, но на этом ноутбуке не выбран по качеству и времени. Для воспроизведения его теста используется `start_model.ps1 -Model 3.5-9b -GpuLayers 24`. Эксперименты с мышлением доступны через `-ReasoningBudget`, по умолчанию оно выключено. При смене модели сначала остановите принадлежащий вам runtime на том же порту.

После подготовки работа не требует скачиваний. Runtime слушает только 127.0.0.1 и запускается с `--offline`. Python-клиент запрещает внешние адреса, proxy и редиректы. Анализируется только видеопоток; звук и идентификация лиц не используются.

## Подключение к сервису после приёмки качества

```powershell
$env:APP_RULE_CATALOG_PATH = "C:\private\verified-rules.json"
.\scripts\start-ml.ps1
```

Оба каталога в репозитории отключены: модель не прошла проверку качества. Скрипт требует отдельный принятый каталог; без него останавливается до запуска модели. Нельзя включать кандидатов только ради зелёного статуса готовности. После приёмки скрипт запускает локальную модель, ждёт готовности и запускает существующий API. Если модель на порту 8091 уже работает, используется этот процесс; его веса нужно сверить с выбранным lock-файлом. Останавливается только процесс модели, созданный этим запуском.

Для раздельного запуска:

```powershell
# Терминал 1
.\ml_tools\start_model.ps1 -Model 3.5-4b
# Терминал 2
$env:APP_ANALYZER_FACTORY = "app.local_analyzer:build_analyzer"
$env:APP_RULE_CATALOG_PATH = "C:\private\verified-rules.json"
.\scripts\start.ps1 -RequireAnalyzer
```

`APP_LOCAL_MODEL_URL` по умолчанию `http://127.0.0.1:8091`. `APP_ML_BUDGET_SECONDS=210` оставляет время для валидации и JPEG в общем лимите сервиса. `APP_ML_FRAMES=12`, `APP_ML_MAX_SIDE=848`. Один GPU обслуживает одну очередь. Модель должна быть запущена до приёма файлов; холодный старт измеряется отдельно от обработки.

## Алгоритм

1. Локальное декодирование с исходными PTS и проверкой конца потока. Хранятся только выбранные JPEG; аудио не декодируется.
2. Общий обзор для длинных видео плюс окна по 24 с с шагом 18 с. В каждом окне до 12 кадров из выборки 2 FPS.
3. Структурированный ответ локальной модели ограничен включёнными процедурами и индексами кадров. Нормативные ссылки в выводе модели запрещены.
4. Повторная проверка каждого кандидата с контекстом операции. Слияние пересекающихся событий одного класса и удаление дубля R20-C/R20-B.
5. Пересчёт индексов в исходные секунды. API извлекает 1–3 настоящих JPEG из загруженного файла.

Неразборчивые фрагменты запрещают отрицательный вердикт, но не удаляют независимо подтверждённые события. Ошибка/таймаут модели не преобразуется в отсутствие нарушения. Метки Excel, имена файлов и заранее известные таймкоды не используются при инференсе.

## Ручные заметки и вторичный разбор ИИ

```powershell
.\.venv\Scripts\python -m ml_tools.reconcile_labels --human "C:\private\open_labels.xlsx" --ai "C:\private\ai-review.xlsx" --output .local_ml/reconciled
```

Сначала создайте manifest командой `python -m ml_tools.dataset "C:\private\videos"`. В `sources.json` сохраняются обе версии, происхождение ячеек и SHA-256 источников. Содержательная заметка человека имеет приоритет. Метка и точка из основной таблицы не заменяются выводом ИИ. «хз» сохраняется как неизвестность, а предложение ИИ остаётся неподтверждённым.

`review-seed.json` можно загрузить в `ml_tools/review.html` через «Продолжить разметку». Полные границы событий не объявляются подтверждёнными: у всех импортированных записей `reviewed=false`, предложения ИИ находятся в заметках, а не в эталонных событиях. Существующую ручную разметку экспортируйте до загрузки другого файла.

## Проверки

```powershell
.\.venv\Scripts\python -m pytest -q --basetemp=.local_ml/tests-new
.\.venv\Scripts\python -m ml_tools.evaluate --mode benchmark --output .local_ml/benchmark-new
.\.venv\Scripts\python -m ml_tools.evaluate --mode dev --output .local_ml/dev-new
.\.venv\Scripts\python -m ml_tools.evaluate --mode video-holdout --output .local_ml/video-holdout-new
# Только после отдельной проверки и активации каталога:
.\.venv\Scripts\python -m ml_tools.smoke "C:\private\video.mov" --rules "C:\private\verified-rules.json" --output .local_ml/api-smoke-new
```

Каталоги результатов должны быть новыми, чтобы не перезаписывать прошлые замеры. `video-holdout` измеряет только разделение целых файлов одной камеры с устранением точных дубликатов. Он не доказывает устойчивость к новому ракурсу. Строгий `holdout` требует ручных интервалов и согласованных непересекающихся групп съёмки. В данном наборе одна камера; все заметки были изучены при разработке, поэтому полностью слепая независимая оценка ещё нужна.

`evaluate` проверяет все ID исследовательского каталога даже при `enabled=false`, сохраняет только приватные предсказания и не выдаёт их через API как проверенные нормативные нарушения. `analyze` без `--evidence` работает аналогично в режиме `research_candidates`; доказательные ответы требуют активного принятого каталога. `evaluate` сохраняет хеши промпта, кода анализатора и каталога. `--model-lock` записывает заявленную версию весов; идентичность работающего сервера этот флаг сам по себе не подтверждает. Для сравнения держите одинаковые выборку, параметры runtime и отсутствие параллельных запросов к GPU.

Веса, видео, Excel, описания эпизодов, JSON разметки, результаты модели и доказательные кадры остаются в `.local_ml/`, `.local_data/` и приватных исходных папках. В GitHub публикуются только код, схемы, публичные источники, lock-файлы и агрегированные результаты.
