# Передача локальной ML-части

Реализация `app.local_analyzer:build_analyzer` совместима с актуальным контрактом сервиса. Она получает длительность и включённые `rule_id`, возвращает наблюдения, исходные таймкоды, полноту и ограничения. JPEG и нормативные ссылки создаёт сервис. Показатели качества и готовность к сдаче: [замеры](ml-measurements.md).

## Подготовка

Windows, Python 3.12 или 3.13, NVIDIA GPU. Замеры человека 2 выполнены на RTX 4050 Laptop 6 ГБ, 16 ГБ ОЗУ и Python 3.12. Текущая машина человека 1 — GTX 1650 Ti 4 ГБ, драйвер 617.42, Python 3.13.15: пригодность той же конфигурации ML здесь ещё не подтверждена. FFmpeg и FFprobe должны находиться в PATH либо `.local_tools/ffmpeg/bin/`. Скрипт установки сервиса создаёт отсутствующий `.env` со случайным ключом, сохраняя существующий.

```powershell
.\scripts\setup.ps1
.\.venv\Scripts\python -m pip install -c constraints.txt -e ".[ml,test]"
.\.venv\Scripts\python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json
```

Последняя команда один раз скачивает публичные веса и runtime и проверяет SHA-256. `model35-lock.json` закрепляет Qwen3.5-4B Q4_K_M, FP16-проектор, ревизию репозитория и llama.cpp b11669. Исходная модель и конверсия распространяются по Apache-2.0. [Исходная модель](https://huggingface.co/Qwen/Qwen3.5-4B), [поставщик GGUF](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF). Старые lock-файлы сохранены для воспроизводимости сравнений.

Более крупный 9B зафиксирован в `model35-9b-lock.json`, но на этом ноутбуке не выбран по качеству и времени. Для воспроизведения его теста используется `start_model.ps1 -Model 3.5-9b -GpuLayers 24`. Эксперименты с мышлением доступны через `-ReasoningBudget`, по умолчанию оно выключено. При смене модели сначала остановите принадлежащий вам runtime на том же порту.

После подготовки работа не требует скачиваний. Runtime слушает только 127.0.0.1 и запускается с `--offline`. Python-клиент запрещает внешние адреса, proxy и редиректы. Анализируется только видеопоток; звук и идентификация лиц не используются.

## Подключение к сервису после приёмки качества

```powershell
$env:APP_RULE_CATALOG_PATH = "C:\private\verified-rules.json"
.\scripts\start-ml.ps1
```

Оба каталога в репозитории отключены: модель не прошла проверку качества. Скрипт требует отдельный принятый каталог; без него останавливается до запуска модели. Нельзя включать кандидатов только ради зелёного статуса готовности. После приёмки скрипт запускает локальную модель, ждёт готовности и запускает существующий API. Если модель на порту 8091 уже работает, используется этот процесс; его веса нужно сверить с выбранным lock-файлом. Останавливается только процесс модели, созданный этим запуском.

Для раздельного запуска:

```powershell
# Терминал 1
.\ml_tools\start_model.ps1 -Model 3.5-4b
# Терминал 2
$env:APP_ANALYZER_FACTORY = "app.local_analyzer:build_analyzer"
$env:APP_RULE_CATALOG_PATH = "C:\private\verified-rules.json"
.\scripts\start.ps1 -RequireAnalyzer
```

`APP_LOCAL_MODEL_URL` по умолчанию `http://127.0.0.1:8091`. `APP_ML_BUDGET_SECONDS=210` оставляет время для валидации и JPEG в общем лимите сервиса. `APP_ML_FRAMES=12`, `APP_ML_MAX_SIDE=848`. Runtime запускается с одним слотом выполнения; сервис принимает один анализ, конкурентный запрос получает HTTP 429 без постановки в очередь. Модель должна быть запущена до приёма файлов. Холодный старт runtime измеряется отдельно от пути API, а для полного запуска учитываются оба времени; фабрика каждой задачи создаёт только клиент.

Защищённый `GET /api/v1/system` показывает `analyzer.runtime` встроенного адаптера отдельно от активных правил. Проба проверяет импорт PyAV, literal loopback-адрес и HTTP 200 от `/health`; HTTP-ожидание ограничено 0,75 секунды, без proxy/редиректов, загрузки весов или передачи кадров. Причины отказа: `ml_dependencies_unavailable`, `analyzer_config_invalid`, `local_model_unavailable`. Перед POST проба повторяется; при неготовности возвращается HTTP 503 без задачи и сохранённого файла. Доступность модели не подтверждает совпадение весов с lock-файлом или качество. Даже отвечающий runtime не позволяет анализ с отключёнными кандидатными правилами. У других фабрик `runtime=null`, и эта проба к ним не применяется.

## Алгоритм

1. Локальное декодирование с исходными PTS и проверкой конца потока. Хранятся только выбранные JPEG; аудио не декодируется.
2. Общий обзор для длинных видео плюс окна по 24 с с шагом 18 с. В каждом окне до 12 кадров из выборки 2 FPS.
3. Структурированный ответ локальной модели ограничен включёнными процедурами и индексами кадров. Нормативные ссылки в выводе модели запрещены.
4. Повторная проверка каждого кандидата с контекстом операции. Слияние пересекающихся событий одного класса и удаление дубля R20-C/R20-B.
5. Пересчёт индексов в исходные секунды. API извлекает 1–3 настоящих JPEG из загруженного файла.

Неразборчивые фрагменты запрещают отрицательный вердикт, но не удаляют отдельные события, поддержанные видимыми условиями. Повторная проверка той же моделью не является независимым подтверждением. Ошибка/таймаут модели не преобразуется в отсутствие нарушения. Метки Excel, имена файлов и заранее известные таймкоды не используются при инференсе.

## Неопределённость: задача человека 2 и передача человеку 1

Сервис подсказывает, какие эпизоды проверить; окончательный вывод делает человек по исходному видео и условиям применимости нормы. Общая точность на наборе, уверенность отдельного ответа и наблюдаемость контекста — разные свойства. В адаптере пока нет валидированного score уверенности. `assessable`, `analysis_complete` и `analysis_scope` не являются вероятностями; проценты «99%» и произвольные уровни уверенности интерфейсу передавать нельзя.

Человеку 2 нужно проверить не только ошибки событий, но и корректность решения «контекста недостаточно»: модель может верно воздержаться на закрытом участке либо необоснованно отказаться на пригодном видео. Измерять ошибки и долю содержательных решений совместно; уменьшение числа ответов не выдавать за рост качества. Короткий протокол, разделение dev/калибровки/финальной проверки, ограничения 42 видео и научные источники: [методика оценки неопределённости](model-evaluation.md#неопределённость-и-передача-решения-человеку).

Для подключения интерфейса передать человеку 1:

1. **Причины неопределённости:** какие проблемы действительно выявляет анализатор, как они проверены человеком и что можно показать пользователю. Не придумывать конкретную причину из общего флага `assessable=false`.
2. **Значения исходов:** когда есть поддержанный наблюдением эпизод, когда возможен полный `no_violation`, когда требуется человеческая проверка из-за недостатка контекста и когда произошла техническая ошибка. Сохранить действующий [контракт](ml-integration.md): два успешных вердикта; без поддержанных событий неполный анализ даёт `failed / insufficient_evidence`, а ошибка runtime/таймаут имеет собственный код. Частичный положительный результат сохраняет ограничения.
3. **Измерения по зафиксированной версии:** TP/FP/TN/FN, события/типы/таймкоды/применимость правил, охват, обоснованные и ложные отказы, технические сбои, размер проверочной части и ограничения независимости. Приложить фактическое время полного пути API.
4. **Синтетические примеры ответов:** положительный, полный отрицательный, частичный положительный, недостаток видимости и техническая ошибка. Использовать существующую схему, без банковских кадров и описаний реальных записей.
5. **Решение о score:** существует ли измеренный и валидированный сигнал уверенности. Если нет — явно это написать. Если есть — указать его цель, версию, метод калибровки, проверочную выборку, охват и доверительные интервалы метрик. Предложение добавить поле или кандидатные события ниже порога согласовать отдельно до изменения схемы.

До такой передачи интерфейс использует кадры, наблюдения, сохранённый охват и ограничения, без численных обещаний надёжности. Он может сообщать «Эпизод требует проверки», «Признаков по проверенным процедурам не найдено» и «Недостаточно контекста для вывода», сохраняя исходный технический результат API в экспорте.

## Ручные заметки и вторичный разбор ИИ

```powershell
.\.venv\Scripts\python -m ml_tools.reconcile_labels --human "C:\private\open_labels.xlsx" --ai "C:\private\ai-review.xlsx" --output .local_ml/reconciled
```

Сначала создайте manifest командой `python -m ml_tools.dataset "C:\private\dataset"`. Передаётся корень набора, а не каталог MOV: внутри должны находиться `open_labels.xlsx` и подпапка `videos/` с видео. Manifest по умолчанию сохраняется в `.local_ml/dataset.json`. В `sources.json` сохраняются обе версии заметок, происхождение ячеек и SHA-256 источников. Содержательная заметка человека имеет приоритет. Метка и точка из основной таблицы не заменяются выводом ИИ. Неопределённые заметки сохраняются как неизвестность, а предложение ИИ остаётся неподтверждённым.

`review-seed.json` можно загрузить в `ml_tools/review.html` через «Продолжить разметку». Полные границы событий не объявляются подтверждёнными: у всех импортированных записей `reviewed=false`, предложения ИИ находятся в заметках, а не в эталонных событиях. Существующую ручную разметку экспортируйте до загрузки другого файла.

## Проверки

```powershell
.\.venv\Scripts\python -m pytest -q --basetemp=.local_ml/tests-new
.\.venv\Scripts\python -m ml_tools.evaluate --mode benchmark --output .local_ml/benchmark-new
.\.venv\Scripts\python -m ml_tools.evaluate --mode dev --output .local_ml/dev-new
.\.venv\Scripts\python -m ml_tools.evaluate --mode video-holdout --output .local_ml/video-holdout-new
# Только после отдельной проверки и активации каталога:
.\.venv\Scripts\python -m ml_tools.smoke "C:\private\video.mov" --rules "C:\private\verified-rules.json" --output .local_ml/api-smoke-new
```

Каталоги результатов должны быть новыми, чтобы не перезаписывать прошлые замеры. `video-holdout` измеряет разделение целых файлов с устранением точных дубликатов. По уточнению пользователя, видео сняты с разных ракурсов; положение кассира не постоянно. Принадлежность роликов к камерам и сессиям не проверена, поэтому этот режим не доказывает устойчивость к новому ракурсу. Строгий `holdout` требует ручных интервалов и согласованных непересекающихся групп съёмки. Все заметки были изучены при разработке, поэтому полностью слепая независимая оценка ещё нужна.

Импорт больше не назначает всем роликам одну камеру: `source_group` и `viewpoint` остаются пустыми до локальной проверки. Старое автоматически подставленное значение `organizer-single-camera` не принимается как подтверждённая группа. Укажите реальную группу съёмки; одинаковые исходники и связанные фрагменты должны оставаться в одной части датасета. Различный ракурс сам по себе не доказывает независимость сессий. Роли кассира и клиента определяются в каждом ролике заново по действиям и устройству рабочего места, без постоянного правила «слева/справа».

`evaluate` проверяет все ID исследовательского каталога даже при `enabled=false`, сохраняет только приватные предсказания и не выдаёт их через API как проверенные нормативные нарушения. `analyze` без `--evidence` работает аналогично в режиме `research_candidates`; доказательные ответы требуют активного принятого каталога. `evaluate` сохраняет хеши промпта, кода анализатора и каталога. `--model-lock` записывает заявленную версию весов; идентичность работающего сервера этот флаг сам по себе не подтверждает. Для сравнения держите одинаковые выборку, параметры runtime и отсутствие параллельных запросов к GPU.

До будущей активации R22 нужно подтвердить, что наблюдается именно приём наличных, к которому относится пункт 22, а не произвольное обслуживание или выдача. Каталог уточняет эту область, но текущий критерий ML `service_started` ещё шире нормы: само начало обслуживания не подтверждает приём наличных. Человеку 2 требуется согласовать критерий и промпт с каталогом, явно проверять вид операции и повторить оценку. Уточнение документации и каталога не исправляет точность распознавания. Действующая [правовая справка](legal-basis.md) не позволяет переносить пункт на любые операции; отключённый исследовательский статус не является подтверждением применимости к конкретной записи.

Веса, видео, Excel, описания эпизодов, JSON разметки, результаты модели и доказательные кадры остаются в `.local_ml/`, `.local_data/` и приватных исходных папках. В GitHub публикуются только код, схемы, публичные источники, lock-файлы и агрегированные результаты.
