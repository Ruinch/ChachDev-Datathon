# Каталог визуальных процедур

Каталог сервиса `app/data/rules.json` содержит два отключённых кандидата R20-A/R20-B, сохранённых из сервисной части. Исследовательский каталог `app/data/ml-rules.json` содержит четыре отключённых кандидата. После проверки с четырьмя ложными тревогами на восьми файлах он также оставлен отключённым. `ml_tools.evaluate` исследует кандидатов локально без активации правил API. Проверка нормативного текста и условий наблюдаемости не равна приёмке точности модели.

Источник: [постановление Правления НБРК № 231 от 29.11.2019](https://adilet.zan.kz/rus/docs/V1900019680), [официальный PDF редакции 16.03.2026](https://zan.gov.kz/api/documents/136659/rus/16.03.2026/download/pdf). Текст пунктов 20 и 22 сверен по сохранённому официальному PDF 17–18.10.2026. В правовой справке участника 1 дополнительно зафиксирована более поздняя редакция 12.07.2026. Дата съёмки неизвестна: применение конкретной редакции к реальной операции остаётся предметом проверки; профиль предназначен для локального эксперимента, а не готового юридического заключения. Модель не определяет номер пункта или URL: сервер берёт их из каталога.

| ID | Наблюдаемый эпизод | Основание | Ограничение |
| --- | --- | --- | --- |
| R20-A | Кассир продолжает приём/пересчёт внесённых денег после ухода клиента | Пункт 20: приём и пересчёт при клиенте | Выход из обрезанного кадра не доказывает отсутствие клиента; внутренний пересчёт исключён |
| R20-B | Деньги завершённой операции остаются вне хранения при следующем клиенте | Пункт 20: хранение ранее принятых денег | Требуется проследить конкретные деньги и смену операций |
| R20-C | Кассир оставляет ранее принятые деньги вне хранения и уходит | Пункт 20: хранение ранее принятых денег | Бумаги не считаются деньгами; текущая обработка и движение к хранилищу исключены |
| R22 | Кассир уходит до завершения подтверждённого приёма наличных от клиента | Пункт 22, параграф о приёме | Выдача, внутренний пересчёт и неизвестный вид операции не подтверждают применимость этой нормы |

Для одного эпизода при следующем клиенте R20-B имеет приоритет над R20-C: два предупреждения об одних деньгах не создаются. Независимые эпизоды возвращаются раздельно. Вывод означает признаки возможного нарушения для проверки человеком.

При объединении уточнены абзацы пункта 20 и область R22 в каталоге. Нынешний ML-признак `service_started` ещё шире подтверждённого приёма наличных. Человеку 2 нужно согласовать его с областью нормы и повторить оценку; текст каталога не исправляет распознавание автоматически. Кандидат остаётся отключённым.

## Темы из ручных заметок, которые нельзя автоматически объявить нарушением

Ручные заметки — основной источник описания действий. Они не заменяют проверку юридического основания и условий его применимости.

- Отсутствие передачи бумажного удостоверения: пункт 19 предусматривает также сервис цифровых документов, пункт 10-1 — электронные кассовые документы. Состояние невидимого экрана не устанавливается по видео.
- Неприменение второго детектора: пункты 9, 19 и 57 требуют соответствующих проверок, но видимый пропуск одного прибора не доказывает отсутствие всех способов проверки.
- Отложенные после пересчёта банкноты могут быть сортировкой или возвратом. Без контекста это не самостоятельное нарушение.
- Открытый сейф, ключи, документы/печати, дверь кассы, работающий ноутбук и электроприборы требуют отдельного применимого основания. Пункты о кладовой нельзя механически переносить на любой ящик или шкаф. Доступ человека к месту работы не доказывает отсутствие у него полномочий.
- Напиток рядом с наличными — наблюдение о риске, но сам по себе не доказательство применимости нормы о личных вещах.
- Выдача без пересчёта — отдельный кандидат по подпункту 4 пункта 31. Нужно видеть всю операцию выдачи и исключить возврат/ранее выполненный пересчёт. В текущий профиль он не включён.

Дополнительный проверяемый источник по устройству помещений — [постановление НБРК № 14, пункт 8](https://adilet.zan.kz/rus/docs/V2000020075). Требование изоляции кассового узла закрывающимся входом само по себе не доказывает неправомерность каждого краткого открывания двери. Этот класс остаётся исследовательским.

## Активация и область проверки

Включённая запись требует `verification="verified"`, `verified_on`, источника, видимых условий и исключений. Наличие нормативного текста не разрешает автоматически выставить этот статус. Приёмка модели не пройдена; результаты опубликованы в [замерах](ml-measurements.md). Для активации нужны проверенные видимые примеры, применимая редакция и приёмка качества на целых видео. Проверка другого ракурса остаётся отдельным требованием.

Частично видимый ролик с независимо подтверждённым событием возвращает `violation` с ограничениями в `analysis_scope`. Если событий нет, а необходимый контекст скрыт, анализатор возвращает `insufficient_evidence`. `no_violation` относится только к включённым процедурам. Нельзя подменять неизвестные классы доказанным отсутствием всех банковских нарушений.

## Правовая справка сервиса

Сохранена справка участника 1 `app/data/legal-guide.json`, доступная через `GET /api/v1/legal-guide`. Она объясняет процедуры и исключения, не активирует правила распознавания и не заменяет нормативную ссылку сохранённого результата. Подробности и история редакций: [правовые основания](legal-basis.md).
