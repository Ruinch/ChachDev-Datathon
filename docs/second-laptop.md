# Запуск всего сервиса на втором ноутбуке

Целевая машина: **Windows, RTX 4050 Laptop 6 ГБ, RAM 16 ГБ**. На ней работают сайт, FastAPI и локальный llama.cpp с Qwen3.5-4B. Браузер получает сайт и API с одного адреса; отдельный хостинг фронтенда и Ollama для текущего адаптера не требуются. Ollama не является взаимозаменяемой заменой поставленного runtime.

На похожей машине измерен инференс этой конфигурации, но **приёмка качества распознавания не пройдена**. Поставляемые правила остаются отключёнными. Установка и зелёный `/health` не исправляют ложные тревоги и пропуски. [Последний протокол](ml-native-video.md).

## 1. Перенести исходники и публичные файлы

Получите актуальную копию исходников своим обычным способом. Не переносите `.venv`: в ней есть ссылки на Python и пути старой машины. Не заменяйте существующую `.env` ноутбука чужой конфигурацией.

Если публичные веса уже скачаны, локально скопируйте в новый корень проекта:

- `.local_ml/models/` — веса и проектор;
- `.local_ml/downloads/` — проверенные исходные ZIP runtime;
- `.local_ml/llama/` — извлечённые EXE/DLL;
- `.local_tools/ffmpeg/bin/` — подготовленные FFmpeg и FFprobe, если они установлены здесь.

Не копируйте весь `.local_ml/` в публичный архив: там могут быть manifest датасета, разметка, предсказания и материалы проверки. Исходные банковские файлы и разметку передавайте только локально разрешённым участникам. Для нового запуска интерфейса старые задачи не нужны; для переноса истории остановите старый API и переносите весь `APP_DATA_DIR`, как описано в [развёртывании](deployment.md#данные-и-восстановление).

## 2. Подготовить Python и локальные инструменты

Установите Python 3.12 с Python Launcher и доступный драйвер NVIDIA. Для запуска тестов интерфейса дополнительно нужен Node.js 22+, для работы сайта он не требуется. Из PowerShell в корне проекта:

```powershell
.\scripts\setup.ps1 -IncludeML -PythonVersion 3.12
```

Если `.venv` на Python 3.12/3.13 уже есть, она сохраняется. Скрипт устанавливает закреплённые пакеты сервиса и ML-клиента, проверяет зависимости и создаёт только отсутствующую `.env` со случайным ключом. Веса он не скачивает. Установите FFmpeg/FFprobe отдельно в указанную выше папку либо пропишите их полные пути в `.env`.

Для предварительной проверки интерфейса без FFmpeg допустим `-AllowMissingMediaTools`; настоящий анализ требует обоих инструментов.

Если файлов модели ещё нет, следующая команда **один раз скачает публичные веса и runtime** с проверкой SHA-256. Датасет она не читает:

```powershell
.\.venv\Scripts\python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json
```

После скачивания или локального переноса проверьте файлы без сети и без их изменения:

```powershell
.\.venv\Scripts\python -m ml_tools.install_runtime --lock ml_tools/model35-lock.json --verify-only
```

Проверяются не только GGUF, но и ZIP, и извлечённые бинарные файлы runtime. При несовпадении не запускайте найденный файл; восстановите его из выбранного lock. Обязательны обе ZIP из lock и соответствующий проектор. Дополнительные модели для сравнения не нужны.

## 3. Сохранить настройки

В локальной `.env` сохраните следующие значения, чтобы раздельный и объединённый запуск использовали одинаковую конфигурацию:

```dotenv
APP_ANALYZER_FACTORY=app.local_analyzer:build_analyzer
APP_RULE_CATALOG_PATH=app/data/ml-rules.json
APP_LOCAL_MODEL_URL=http://127.0.0.1:8091
APP_ML_INPUT_MODE=video
APP_ML_FRAMES=24
APP_ML_MAX_SIDE=848
APP_ML_BUDGET_SECONDS=210
HF_HUB_OFFLINE=1
TRANSFORMERS_OFFLINE=1
```

Существующий `APP_API_KEY` оставьте собственным секретом. Относительные пути скрипты разрешают от корня проекта. Переменные, уже заданные в текущем PowerShell, имеют приоритет над `.env`; для повторяемого запуска открывайте свежий терминал. Для отдельного файла используйте одинаковый `-EnvPath` у setup, start-ml, check и export-runtime-report.

Не включайте кандидаты в `ml-rules.json` ради запуска: сайт будет доступен, анализ останется закрыт до приёмки. Каталог принятого набора правил подключается отдельно после проверки качества, наблюдаемости и правовой применимости.

## 4. Проверить и запустить

```powershell
# Проверка пакетов, медиоинструментов и хешей без запуска процессов:
.\scripts\start-ml.ps1 -CheckOnly

# Модель и сайт; оставить окно открытым:
.\scripts\start-ml.ps1
```

Откройте `http://127.0.0.1:8000/`, введите ключ из локальной `.env`. Runtime слушает только `127.0.0.1:8091`. Он запускается с одним слотом, контекстом 16384, GPU layers `all`, reasoning off, visual tokens 256–768 и `--offline`. Это параметры последнего протокола, а не гарантия качества. Прогрев модели ограничен 90 секундами; при ошибке CUDA или нехватке памяти настройку проверяют отдельно, не подменяя модель незаметно.

Если на 8091 уже работает модель, объединённый запуск останавливается. Остановите принадлежащий вам старый runtime либо явно укажите `-UseExistingModel` после сверки его весов и параметров. Проверка локальных файлов не доказывает, что чужой процесс использует именно их. `Ctrl+C` завершает API и только runtime, созданный этим запуском.

Во втором PowerShell:

```powershell
.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000
.\scripts\export-runtime-report.ps1 -VerifyModel
# Для тестов нужен Node.js 22+:
.\scripts\check.ps1 -RunTests
```

Пока каталог отключён, `ready=false` ожидаем и анализ возвращает 503. Отчёт среды сохраняется локально в `.local_data/scratch/`: версии пакетов/GPU и хеши кода, каталога и lock, без ключа, видео и разметки. `model_files_verified=true` подтверждает файлы, а не точность или готовность публичного сервиса.

## 5. После приёмки качества

Подключите принятый каталог в `.env`, перезапустите и выполните строгую проверку:

```powershell
.\scripts\start-ml.ps1 -RequireAnalyzer
# В другом окне:
.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RequireAnalyzer
```

Затем пройдите полный путь загрузки, событий, таймкодов, настоящих JPEG, повторного открытия задачи, отказа при недостатке контекста и восстановления после перезапуска. Для проверок сервиса используйте синтетическое видео, для качества — только локальную отложенную проверку. Замерьте полный путь самого длинного MOV, включая холодный старт модели отдельно. Очереди нет: одновременный второй анализ получает 429.

Проверка автономности: после подготовки файлов остановите API и свой runtime, заблокируйте исходящий интернет для анализатора, снова запустите и выполните анализ. Одних offline-флагов недостаточно. При проверке жюри входящий публичный HTTPS должен оставаться доступен.

Публикацию выполняет владелец: HTTPS-прокси/туннель направляется на `127.0.0.1:8000`, **порт модели 8091 не публикуется**. С внешней сети проверьте доступ, авторизацию, загрузку, опрос результата и видеоплеер с Range. Ноутбук должен оставаться включённым, подключённым к питанию и без сна. Инструкция прокси и резервного копирования: [развёртывание](deployment.md).

## Что не подтверждается этим запуском

- Доступность процесса не доказывает распознавание по требованиям ТЗ.
- Дообучение имеет отдельные требования к проверенной разметке, разбиению и памяти; возможность инференса 4B на 6 ГБ не означает возможность обучения 4B на этой же GPU.
- Публичный адрес и прогон с заблокированным исходящим интернетом проверяются на ноутбуке отдельно.
