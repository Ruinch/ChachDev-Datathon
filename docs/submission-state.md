# Состояние варианта для сдачи

18 октября 2026 года. Проект можно показывать как работающий локальный прототип с экспериментальными наблюдениями. **Приёмка автоматического выявления нарушений не пройдена.** Дообученных весов нет; ограничения в интерфейсе и отключённые строгие каталоги сохранены.

## Что реально проверено

- FastAPI раздаёт сайт и API на ноутбуке; отдельный llama.cpp выполняет Qwen3.5-4B Q4_K_M локально. Веса и runtime закреплены в `ml_tools/model35-lock.json`.
- В последнем полном прогоне 39 уникальных видео: 5 TP, 3 FP, 15 TN, 15 FN и 1 неопределённый результат. Совпадений с общими исходными метками 20/39. Это набор разработки, не независимый тест новых камер; метки охватывают и другие процедуры.
- В прогоне V16 медиана работы анализатора 8,34 с, максимум 94,95 с. Отдельный функциональный проход через работающий API занял 29,59 с от начала загрузки; три JPEG совпали с извлечением из исходного видео. Один такой проход не подтверждает общий предел 300 секунд через внешнюю сеть.
- После изменений разметчика и подготовки обучения прошли **521 Python-тест** (170,26 с) и **80 JavaScript-тестов**. Python запускался со свежим `--basetemp` внутри `.local_data/`, поскольку стандартный каталог временных файлов недоступен по ACL. Синтаксис нового запускателя проверен; `restart-laptop.ps1 -CheckOnly` подтвердил текущую конфигурацию без остановки процессов. Тесты сервиса не измеряют точность модели.
- Оборудование: RTX 4050 Laptop 6141 МиБ, Ryzen 5 7535HS, 15,25 ГиБ доступной системе RAM; Python 3.12.8, llama.cpp b11669 / CUDA 12.4.

Подробные измерения и границы сравнения: [V16](ml-quality-v16.md). Численная уверенность отдельного события не откалибрована. Повторение ответа той же моделью не является независимой проверкой.

## Что подготовлено для исправления ошибок

Локально сформирована очередь из 18 уникальных видео: сначала три ложные тревоги, затем пятнадцать пропусков относительно меток организаторов. В каждой карточке — первичные человеческие заметки, общие вопросы по условиям класса и исходные временные ориентиры. Прежний сохранённый черновик перенесён; гипотезы стороннего ИИ не приняты за эталон. Старые файлы сохранены.

Разметчик работает только на `http://127.0.0.1:8767/`, сохраняет изменения на ноутбуке и не должен публиковаться через Funnel. Порядок заполнения: [инструкция разметки](annotation-errors.md). После перезагрузки, из корня проекта:

```powershell
.\scripts\start-error-review.ps1
```

Очередь и банковские файлы намеренно отсутствуют в Git. На другой машине надо подготовить собственную приватную очередь и передать её через `-QueuePath`.

Полная разметка видео ещё не является готовым ответом для выбранных обучающих кадров. Проверяются группы исходных съёмок, независимость train/validation, видимость всех условий на точной выборке и неоднозначность. Порядок обучения: [дообучение](finetuning.md). Текущий рецепт bf16 LoRA для 4B не помещается в предварительный лимит 6 ГБ VRAM; меньшая модель требует отдельного эксперимента и не заменяет рабочую автоматически.

Для дальнейшей проверки локально извлечены 21 окно и 84 JPEG из 14 уникальных dev-источников. Четыре защищённых источника очереди не использованы; все защищённые SHA исходного manifest сохранены. Ответы пустые, подтверждённых train/validation окон нет. Команда `ml_tools.review_readiness` проверяет сохранённые целые видео и условия экспорта источников, но не создаёт ответы для кадров и не объявляет обучение готовым.

## Публичный показ и оставшиеся условия

Схема: публичный HTTPS → Tailscale Funnel → FastAPI `127.0.0.1:8000`; модель `127.0.0.1:8091` и разметчики остаются локальными. Порядок запуска и восстановления: [ноутбук жюри](jury-laptop.md), [эксплуатация](laptop-operations.md).

Показывать можно загрузку MOV, экспериментальные наблюдения, таймкоды, исходные JPEG, сохранение и повторное открытие задачи. Пустой список наблюдений не является подтверждением отсутствия нарушений. Строгий `/api/v1/analyze` остаётся закрытым до приёмки качества; рабочий экспериментальный маршрут — `/api/v1/review`.

До полной сдачи остаются: подтверждённая разметка и новый независимый набор; обучение/оценка принятого кандидата; проверка реального холодного запуска и автономности; загрузка MOV из другой сети с лимитом приёма 30 секунд; повторная проверка всего пути до 300 секунд. Публичный показ требует работающих интернета, Funnel, API и модели. Общий API-ключ открывает весь журнал: для жюри нужен чистый профиль и передача ключа отдельно от JavaScript/URL.

Публикация кода не исправляет эти ограничения и не меняет показатели качества. Банковские данные, кадры, разметка, веса и секреты не включаются в коммит.
