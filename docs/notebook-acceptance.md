По сравнению со старым отчётом с четырьмя FP на восьми файлах ложных тревог меньше, но TP тоже уменьшилось: качество не принято. Подробности алгоритма и сравнений — [отчёт V12](ml-native-video.md).

## Реальный HTTP и регрессии

После объединения с `e835bf8` повторены проверки через настоящий TCP HTTP → FastAPI → изолированный процесс → локальную Qwen. Отдельный приватный синтетический каталог позволяет проверить передачу ссылок; он не используется как принятое правовое основание и не скопирован в профиль жюри.

| Сценарий | Результат | От начала POST до результата |
| --- | --- | ---: |
| Самый длинный отрицательный, 142,53 с / 27,39 МиБ | done / no_violation | 59,703 с |
| Положительный ориентир из человеческой заметки | done / violation, 1 событие, 2 валидных JPEG | 23,250 с |
| Недостаточный контекст | failed / insufficient_evidence, без вердикта | 25,157 с |

Загрузка длинного файла в loopback заняла 0,157 с, ответ 202 с учётом FFprobe — 0,266 с. Это не скорость внешнего канала. Во всех трёх случаях подтверждены Range оригинала, его SHA-256, наличие в журнале и повторное чтение результата. После остановки и нового запуска API все три результата сохранились. Конкурентный POST при настоящем анализе получил 429. Ссылки событий совпали с серверным тестовым каталогом; смысл кадров/применимость нормы этим не проверены.

После обновления runtime заново остановлен и запущен через новый запускатель: **16,109 с** включая проверку локальных файлов и загрузку модели. При остановленной модели API вернул 503 без создания задачи. Тот же большой MOV с ограничением отправки 10 Мбит/с: тело **22,985 с**, ответ 202 **23,110 с**, полный POST → результат **85,828 с**; от старта runtime через проверку исходника после результата — **102,250 с**. Это холодный процесс модели, но не перезагрузка Windows и не пустой дисковый кеш.

При 5 Мбит/с получен **408 / upload_timeout за 31,008 с**, задача не создана, слот освобождён. Первые две попытки этого вспомогательного curl-теста не дошли до API: путь с кириллицей передавался через CP1251, curl завершался с кодом 26. Минимальное воспроизведение локализовало причину, явный UTF-8 исправил проверку. Рабочий Python-клиент передаёт бинарный multipart и этого дефекта не имел. Приватные результаты сохранены отдельно; неудачные попытки не засчитываются как успешные тесты. Замеры ограниченной отправки остаются локальными, не доказывают скорость Funnel.

Несколько событий и четыре исходных JPEG проверены новым клиентом через настоящий HTTP на сгенерированном MOV и детерминированном тестовом анализаторе. Отдельные существующие тесты проверяют остановленный runtime, ошибку/таймаут анализатора, неполный контекст и восстановление прерванной задачи. Синтетический анализатор не выдаётся за Qwen.

Общий прогон: **239 Python-тестов без пропусков (48,94 с), 56 JavaScript-тестов**, проверки Windows-запускателей; одно предупреждение сторонней связки Starlette/httpx. Для нового профиля и HTTP-клиента сначала получен падающий тест отсутствующего поведения, затем проходящий. Проверка профиля подтверждает изоляцию от личных `APP_*` и отказ анализа с отключёнными правилами. После изменения параметров `start-ml.ps1` новый тест обнаружил отсутствие обязательной проверки каталога в обычном запуске профиля; добавлен явный `-RequireAnalyzer`, тест стал проходить. Повторное использование уже работающей модели теперь требует явного `-UseExistingModel`. Применены указанные пользователем принципы Matt Pocock: проверки через публичные интерфейсы и отдельный модуль запуска, без переделки сервиса.

Новый `start_model.ps1 -CheckOnly` проверил настоящие локальные веса, ZIP и извлечённые DLL/EXE по lock без сети. Создан приватный отчёт окружения `.local_ml/notebook-runtime-e835.json`. Инструменты подготовки LoRA из нового `main` сохранены и включены в общий тестовый прогон; CUDA-обучение не запускалось, новых обученных весов нет.

Начать с уже подготовленной приватной очереди `.local_ml/review-temporal-v12`: `Проверить.txt`, `dataset.json`, `review-seed.json` и `priority.json`. Это 10 спорных записей / 8 уникальных видео, а не новые эталонные ответы. Неподтверждённую группу не отмечать проверенной. Сначала человеческая разметка; затем диагноз FP/FN и настройка на dev. Для обучения из нового `main` следовать [протоколу подготовки точных окон](finetuning.md). ## Продолжение: локальный сервер и очередь разметки

При последней сверке main продвинулся до `58dec8b`: изменён только README. Его новая редакция сохранена, ссылки на локальный запуск и разметку добавлены поверх. Код сервиса и ML при этом не менялся. Итоговый patch продолжения основан на `58dec8b`; HEAD и реальный индекс по-прежнему не перемещались.

По новому запросу владелец разрешил установить Tailscale, открыть Funnel и настроить ноутбук как сервер. Tailscale 1.104.1 установлен через winget с проверкой хеша пакета; владелец вошёл в свой аккаунт и разрешил Funnel. `tailscale set --unattended=true` выполнен. Публичный HTTPS-адрес: https://wadags-laptop.tail32787c.ts.net/ — прокси только к `127.0.0.1:8000`.

Проверка HTTPS с ноутбука: главная 200, API без ключа 401, авторизованные system/history 200, Qwen runtime ready, журнал пуст; `/queue.json`, `/video/0`, `/.local_ml/`, `/.env` возвращают 404. Первое подтверждение другой сети владелец отозвал: он открывал URL на этом же ноутбуке. Затем после дополнительной проверки сообщил, что другое устройство открывает сайт. Google и Cloudflare DoH возвращают три публичных адреса Funnel; принудительный curl через каждый из них дал 200 с корректной TLS-проверкой примерно за 1,1 с. Обычный DNS ноутбука возвращает внутренний адрес Tailscale и не проверяет публичный маршрут. Причина краткого внешнего сбоя не доказана; до 10 минут DNS propagation допускает официальная документация. Внешняя загрузка MOV и время полного анализа не проверены; отключённый каталог намеренно блокирует анализ.

Для разметки запущен отдельный сервер `127.0.0.1:8766`, вне Funnel. Подготовлена `.local_ml/review-eight-human-v1/queue.json`: 8 исходников / 8 SHA, без переноса машинных гипотез в эталон, 0 подтверждённых событий, старые файлы сохранены. Сервер проверяет хеши, Host/Origin, отдаёт только выбранные MOV и поддерживает Range. Исходные файловые пути не входят в HTTP manifest. Обычный file:// просмотрщик сохранён. Инструкция: [разметка восьми видео](../ml_tools/РАЗМЕТКА_8_ВИДЕО.md).

Добавлен `-StartModel` у профиля: `-InterfaceOnly -StartModel` запускает Qwen и кабинет с отключёнными правилами, а обычный запуск по-прежнему требует принятого каталога. Пройден полный набор **243 Python + 56 JavaScript**, затем отдельно прошли новый тест журналирования ошибки запуска и новый synthetic JS-тест автозагрузки очереди (8/8 тестов разметчика). Тесты не подтверждают качество ML. `run-laptop.ps1 -CheckOnly` прошёл на реальных весах без запуска новых серверов. Журналы startup хранятся только в закрытом профиле.

Планировщик возвращал 1 даже на синтетическом cmd echo без ML; точная причина не установлена. Созданная диагностическая задача архивирована и удалена. Вместо неё создан ярлык текущего пользователя Startup, вызывающий run-laptop.ps1. Его фактический запуск восстановил FastAPI и Qwen, локальный API и публичная главная дали 200.
