# Учёт задач: локальные Markdown-файлы

В этом проекте задачи и спецификации хранятся в `.local_data/scratch/`, которая уже исключена из Git. Этот путь заменяет стандартную `.scratch/` из шаблонов навыков.

## Структура

- Одна функция или доработка: `.local_data/scratch/<feature>/`.
- Спецификация: `spec.md` внутри этой папки.
- Задачи: отдельный файл `issues/01-<slug>.md`, `issues/02-<slug>.md` и далее. Не объединять все задачи в один файл.
- Для обычной задачи указать `Status: open`, `in-progress`, `blocked` или `done`. Это локальные состояния; интеграция `/triage` не настроена.
- Комментарии добавлять в конец файла под `## Comments`.
- Не создавать задачи и спецификации заранее, если пользователь не поручил соответствующую работу.

## Публикация и получение задачи

Если навык предлагает «опубликовать в трекере», создать локальный файл в указанной папке. Если требуется «получить задачу», прочитать переданный пользователем путь. Внешний трекер, репозиторий и его метки не изменять.

Коммиты, ветки, push, GitHub Issues, PR, комментарии, метки и публикацию выполняет пользователь. Для такой операции агент готовит только локальный черновик.

## Работа `/wayfinder`

- Карта исследования: `.local_data/scratch/<effort>/map.md` с разделами Notes, Decisions-so-far и Fog.
- Отдельная задача: `issues/NN-<slug>.md` с `Type: research`, `prototype`, `grilling` или `task`.
- В этом процессе используются состояния `open`, `claimed`, `resolved` и строка зависимостей `Blocked by: NN, NN`.
- Сначала сохранить `claimed`, затем начать работу. При завершении добавить ответ в `## Answer`, установить `resolved` и записать вывод со ссылкой в карту.
- Эти состояния отдельного процесса не означают наличие установленных навыков или меток внешнего трекера.

## Содержимое

Не копировать сюда кадры, описания конкретных банковских записей, ключи и содержимое таблиц разметки ради постановки сервисной задачи. Ссылаться на локальные материалы без их раскрытия.
