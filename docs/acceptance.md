# Проверка перед сдачей

Этот список выполняется на машине, где будет работать сервис. Рядом с пунктами сохраните дату, конфигурацию модели и фактический результат. Пройденные проверки инфраструктуры не подтверждают качество распознавания.

## Можно проверить до готовности модели

- Запуск из проектной `.venv`, собственный ключ в `.env`, проверка настроек и доступности FFmpeg/FFprobe.
- Главная страница, загрузка/выбор файла, работа на узком экране и с клавиатурой; сообщения об ошибках читаемы.
- `GET /api/v1/system`: без ключа HTTP 401, с ключом — фактическая готовность, ограничения и состояние инструментов. Без модели/проверенных правил `ready=false`, загрузка для анализа не создаёт фиктивного результата.
- Проверка API-контракта и отказов командой `.\scripts\check.ps1 -AllowMissingMediaTools -RunTests`. Это проверки кода; они не заменяют приёмку настоящего видео.
- Отсутствие ключа в адресах, исходниках и выгружаемых JSON; `.env`, видео, результаты и веса исключены из Git.

## После подключения адаптера человека 2

- Каталог содержит только включённые проверенные правила с документом, пунктом, источником и условиями применимости. Анализатор действительно проверяет все включённые правила; неполный анализ не превращается в `no_violation`.
- `.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RequireAnalyzer` проходит: модель настроена, правила готовы, FFmpeg/FFprobe доступны.
- Один настоящий `.mov` проходит путь `HTTP 202 → processing → done`. JSON соответствует ТЗ, а результат сохраняется после обновления страницы/повторного получения по `job_id`.
- Положительный ролик даёт подтверждаемый эпизод, отрицательный — не даёт ложного. Отдельно проверен ролик с несколькими событиями, другой ракурс и частичная видимость. Сводка TP/FP/FN и ошибок времени записана на отложенной части датасета.
- `analysis_scope` сохраняется в API, интерфейсе и экспорте. Подтверждённый эпизод частично проверенного видео остаётся доступен с `full_video_checked=false` и ограничениями. Неполная проверка без подтверждённых событий не выдаёт `no_violation`.
- Переход из события устанавливает правильный таймкод исходного видео. Для каждого события присутствуют 1–3 настоящих JPEG; их время находится в границах записи. Нормативная ссылка соответствует наблюдаемому действию.
- Одинаковый вывод доступен через интерфейс и API; экспорт JSON читается независимо от браузера.
- Расширение `.mov` у текстового/повреждённого файла не обходит проверку. Проверены пустой файл, неподдерживаемая запись, лимит размера и лимит длительности. Медленная загрузка сверх `APP_UPLOAD_TIMEOUT_SECONDS` получает HTTP 408. Возвращается понятный отказ без зависшего задания; после обрыва соединения/таймаута следующая задача принимается.
- Два одновременных запроса: принята только одна задача, вторая получает HTTP 429. После завершения/отказа обработчик принимает новую задачу.
- При зависании адаптера срабатывает таймаут, задача становится `failed`, процесс освобождается. Проверка проведена контролируемым тестовым адаптером, который никогда не включается в демонстрацию распознавания.
- При перезапуске сервера исходные файлы и завершённые результаты сохраняются, прерванная задача помечается `failed`, новая задача обрабатывается. Попытка второго запуска с тем же каталогом данных отвергается блокировкой.
- Запросы к статусу и исходному видео без ключа или с неверным ключом получают HTTP 401; несуществующий `job_id` с верным ключом получает HTTP 404. Используется один общий ключ с доступом ко всем задачам; отдельных аккаунтов и разграничения по пользователям нет. Перемотка защищённого видео работает в выбранном браузере.

## На машине сдачи

- После холодного запуска короткий и самый длинный ролики обработаны полностью. Замер включает загрузку, проверку видео, старт модели, анализ, кадры и получение результата клиентом. Оба укладываются в 300 секунд; целевой запас — серверная обработка менее 240 секунд.
- После отключения исходящего интернета сервер перезапущен и повторён полный анализ; нет скачивания весов, внешних шрифтов/скриптов или AI-запросов.
- Достаточно диска для входных файлов и доказательств; установлен режим работы без сна, процесс переживает отключение личного терминала и перезагрузку согласно выбранному способу запуска.
- Публичные интерфейс и API открываются из другой сети по HTTPS; настоящий ключ передан жюри отдельно. Проверены лимит загрузки и задержки через внешний адрес.
- Подготовлены инструкция запуска, схема устройства, версии/веса модели, список распознаваемых процедур, источники правил и известные ограничения. Качество и скорость описаны результатами измерений.

Не используйте точные дубликаты видео как независимые примеры. Спорные отметки исходной разметки нужно согласовать до подсчёта качества; протокол находится в [model-evaluation.md](model-evaluation.md).

## Выполнено локально 17 октября 2026

Среда: Windows, Python 3.13, проектная `.venv`, FFmpeg/FFprobe 9.0.2. Все 61 автоматическая проверка прошли с доступными медиоинструментами. Одно предупреждение относится к устаревающей связке Starlette TestClient/httpx. Проверка синтаксиса трёх модулей интерфейса также прошла.

Интеграционный прогон использовал только сгенерированные тестовые MOV и временный тестовый адаптер: проверены настоящие JPEG, несколько событий, полная отрицательная и частичная положительная проверки, авторизация исходника и диапазоны байтов. Это не проверка распознавания банковских процедур. Тестовый адаптер и его задания удалены; основной сервис запущен без модели и с выключенными кандидатными правилами.

В браузере проверены плеер и точный переход к эпизоду без автоматического воспроизведения, увеличение и переключение кадров, восстановление задачи после обновления с повторным вводом ключа, ограничения частичного анализа и копирование JSON. На ширинах 320, 768 и 1440 пикселей горизонтальной прокрутки страницы нет. Сохранение JSON через ссылку во встроенном браузере подтвердить не удалось; копирование сработало, предусмотрено ручное выделение текста. В `/docs` проверены локальные ресурсы, авторизация и успешный запрос `/api/v1/system`.

Ещё не проверены: реальная модель, применимость нормативных пунктов, качество и время анализа датасета, полный запуск с моделью без исходящего интернета и публичный HTTPS-адрес. Эти проверки обязательны после интеграции.
