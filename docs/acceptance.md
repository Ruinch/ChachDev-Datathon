# Проверка перед сдачей

Этот список выполняется на машине, где будет работать сервис. Рядом с пунктами сохраните дату, конфигурацию модели и фактический результат. Пройденные проверки инфраструктуры не подтверждают качество распознавания.

## Условия готовности по ТЗ

1. Новая запись автоматически проходит путь от загрузки до результата через интерфейс и API, без ручного запуска кода для отдельного видео.
2. Реальная модель выдаёт подтверждаемые вердикты и события с типом, точным таймкодом, 1–3 исходными JPEG и обоснованной нормативной ссылкой; неполная проверка обозначена явно.
3. Сервис сохраняет результаты, корректно обрабатывает ошибки и освобождается после сбоев; пользователь может вернуться к проверке после обновления страницы или перезапуска сервера.
4. Полный холодный цикл занимает не более 300 секунд и работает после подготовки весов без исходящего интернета.
5. Публичные интерфейс и API доступны по HTTPS из другой сети; жюри получает ключ, инструкции, описание моделей, процедур и измеренных ограничений.

История, каталог и печать отчётов повышают удобство работы. Они не подтверждают качество распознавания, лимит пяти минут или доступность публичного адреса.

## Можно проверить до готовности модели

- Запуск из проектной `.venv`, собственный ключ в `.env`, проверка настроек и доступности FFmpeg/FFprobe.
- Главная страница, загрузка/выбор файла, работа на узком экране и с клавиатурой; сообщения об ошибках читаемы.
- Навигация между журналом, новой проверкой, результатом, процедурами и подключением работает с кнопками браузера «назад/вперёд» и прямыми ссылками. Пустой журнал, отсутствие результатов поиска и недоступный сервер имеют понятные состояния.
- Один ввод верного ключа открывает журнал, каталог и защищённые результаты в течение работы страницы. Ключ не появляется в `localStorage`, `sessionStorage`, URL, JSON и печатном отчёте. После обновления страницы требуется повторный ввод; неверный ключ не открывает данные.
- `GET /api/v1/system`: без ключа HTTP 401, с ключом — фактическая готовность, ограничения и состояние инструментов. Без модели/проверенных правил `ready=false`, загрузка для анализа не создаёт фиктивного результата.
- `GET /api/v1/jobs` и `GET /api/v1/rules` без ключа или с неверным ключом возвращают HTTP 401. С верным ключом журнал и каталог работают независимо от готовности ML. Элементы журнала не содержат изображений и полных описаний событий.
- В журнале проверены поиск по имени, фильтры `status`/`verdict`, переходы страниц и сброс фильтров. `total` соответствует фильтру, `summary` — всем задачам. Записи не теряются и не дублируются при переходе страниц без изменения набора задач. Границы `limit` 1–100 и неотрицательное `offset` валидируются; поиск символов `%`/`_` трактуется как буквальная подстрока.
- Открытие строки журнала запрашивает полный результат по `job_id`; защищённый исходник загружается отдельно с ключом, без его передачи в URL. Завершённая проверка снова доступна из журнала после обновления страницы и повторного подключения. Для наполненного журнала допустим изолированный прогон на синтетическом видео с контролируемым тестовым адаптером; его результаты не являются демонстрацией распознавания.
- Временная ошибка GET статуса вызывает до четырёх повторов через 1/2/4/8 секунд; после восстановления результат появляется автоматически, после исчерпания попыток доступно ручное обновление. Нет второго POST, потери выбранного файла или применения ответа из старой сессии.
- При потерянном, нечитаемом или неопределённом ответе создания задачи видна ссылка «Проверить журнал». Предупреждение остаётся доступным и в разделе разбора; параллельный 401 не скрывает неопределённость принятия. Достоверный отказ загрузки не обозначается как возможное принятие.
- Результат и содержимое отчёта показывают сохранённые ID проверенных процедур, состав задачи и ограничения, когда они различаются. Старый результат без `analysis_scope` не выдаётся за полную проверку по сегодняшнему каталогу.
- На синтетическом MOV проверены начало, обычная позиция между кадрами и позиция после последнего PTS до конца контейнера. Существующий последний кадр извлекается, его запрошенная отметка просмотра сохраняется; повреждённый файл и недопустимые отметки не получают подставного изображения.
- Каталог показывает актуальные статусы, нормативные ссылки, признаки, контекст и ограничения. Поставляемые кандидаты отключены и не названы распознаваемыми процедурами. Просмотр раздела не активирует правила, а недоступный каталог не превращается в пустой успешный список.
- Проверка API-контракта и отказов командой `.\scripts\check.ps1 -AllowMissingMediaTools -RunTests`. Это проверки кода; они не заменяют приёмку настоящего видео.
- Отсутствие ключа в адресах, исходниках и выгружаемых JSON; `.env`, видео, результаты и веса исключены из Git.

## После подключения адаптера человека 2

- Каталог содержит только включённые проверенные правила с документом, пунктом, источником и условиями применимости. Анализатор действительно проверяет все включённые правила; неполный анализ не превращается в `no_violation`.
- `.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RequireAnalyzer` проходит: модель настроена, правила готовы, FFmpeg/FFprobe доступны.
- Один настоящий `.mov` проходит путь `HTTP 202 → processing → done`. JSON соответствует ТЗ, а результат сохраняется после обновления страницы/повторного получения по `job_id`.
- Положительный ролик даёт подтверждаемый эпизод, отрицательный — не даёт ложного. Отдельно проверен ролик с несколькими событиями, другой ракурс и частичная видимость. Сводка TP/FP/FN и ошибок времени записана на отложенной части датасета.
- `analysis_scope` сохраняется в API, интерфейсе и экспорте. Подтверждённый эпизод частично проверенного видео остаётся доступен с `full_video_checked=false` и ограничениями. Неполная проверка без подтверждённых событий не выдаёт `no_violation`.
- Переход из события устанавливает правильный таймкод исходного видео. Для каждого события присутствуют 1–3 настоящих JPEG; их время находится в границах записи. Нормативная ссылка соответствует наблюдаемому действию.
- Одинаковый вывод доступен через интерфейс и API; экспорт JSON читается независимо от браузера.
- «Печать отчёта» включает все события, а не только открытое, с таймкодами, описаниями, кадрами и нормативными источниками. В отчёте сохраняются вердикт, охват и ограничения частичного анализа. В предпросмотре/сохранённом PDF нет элементов управления, ключа и обрезанного текста; кадры читаемы, длинный отчёт корректно разбит на страницы. Вызов диалога печати сам по себе не подтверждает качество PDF.
- Расширение `.mov` у текстового/повреждённого файла не обходит проверку. Проверены пустой файл, неподдерживаемая запись, лимит размера и лимит длительности. Медленная загрузка сверх `APP_UPLOAD_TIMEOUT_SECONDS` получает HTTP 408. Возвращается понятный отказ без зависшего задания; после обрыва соединения/таймаута следующая задача принимается.
- Два одновременных запроса: принята только одна задача, вторая получает HTTP 429. После завершения/отказа обработчик принимает новую задачу.
- При зависании адаптера срабатывает таймаут, задача становится `failed`, процесс освобождается. Проверка проведена контролируемым тестовым адаптером, который никогда не включается в демонстрацию распознавания.
- При перезапуске сервера исходные файлы и завершённые результаты сохраняются, прерванная задача помечается `failed`, новая задача обрабатывается. Попытка второго запуска с тем же каталогом данных отвергается блокировкой.
- Запросы к статусу и исходному видео без ключа или с неверным ключом получают HTTP 401; несуществующий `job_id` с верным ключом получает HTTP 404. Используется один общий ключ с доступом ко всем задачам; отдельных аккаунтов и разграничения по пользователям нет. Перемотка защищённого видео работает в выбранном браузере.

## На машине сдачи

- После холодного запуска короткий и самый длинный ролики обработаны полностью. Замер включает загрузку, проверку видео, старт модели, анализ, кадры и получение результата клиентом. Оба укладываются в 300 секунд; целевой запас — серверная обработка менее 240 секунд.
- После отключения исходящего интернета сервер перезапущен и повторён полный анализ; нет скачивания весов, внешних шрифтов/скриптов или AI-запросов.
- Достаточно диска для входных файлов и доказательств; установлен режим работы без сна, процесс переживает отключение личного терминала и перезагрузку согласно выбранному способу запуска.
- Публичные интерфейс и API открываются из другой сети по HTTPS; настоящий ключ передан жюри отдельно. Проверены лимит загрузки и задержки через внешний адрес.
- Подготовлены инструкция запуска, схема устройства, версии/веса модели, список распознаваемых процедур, источники правил и известные ограничения. Качество и скорость описаны результатами измерений.

Не используйте точные дубликаты видео как независимые примеры. Спорные отметки исходной разметки нужно согласовать до подсчёта качества; протокол находится в [model-evaluation.md](model-evaluation.md).

Ещё не проверены: реальная модель, применимость нормативных пунктов, качество и время анализа датасета, полный запуск с моделью без исходящего интернета и публичный HTTPS-адрес. Эти проверки обязательны после интеграции.

Применены рекомендации `codebase-design` из `mattpocock/skills`: жизненный цикл задачи, запись файлов и передача обработчику собраны в `JobService`; HTTP-ограничения отделены от маршрутов. Код анализатора, worker, извлечения доказательств, правил и контракт интеграции человека 2 в этом этапе не изменялись.

Итоговый запуск `.\scripts\check.ps1 -BaseUrl http://127.0.0.1:8000 -RunTests` прошёл: **81 Python-проверка**, **21 JavaScript-проверка** и проверки сценариев установки/запуска. Среда — Windows, Python 3.13 и настоящие FFmpeg/FFprobe 9.0.2. Сохраняется одно предупреждение сторонней связки Starlette TestClient/httpx. Проверка синтаксиса пяти модулей JavaScript прошла. Независимая проверка выявила и помогла исправить повторную отмену HTTP-запроса во время сохранения видео: слот и входной файл теперь остаются заняты до завершения сохранения и передачи обработчику либо завершённой очистки. Регрессионный тест выполняет две отмены, проверяет ответ `429` конкурентной загрузке, целостность сохранённого видео и завершение исходной задачи. В изолированном экземпляре браузер прошёл полный путь на сгенерированном двухсекундном MOV: выбор файла → переход к подключению с сохранением выбора → загрузка → обработка → два события. Переход в журнал во время обработки не прерывает опрос и не возвращает пользователя самопроизвольно на результат. Проверены открытие результата из журнала, восстановление после обновления и повторного ввода ключа, загрузка защищённого исходника, переход к 1,2 секунды без автоматического воспроизведения, увеличение настоящего извлечённого кадра и закрытие по Escape. В этом окружении автоматизация встроенного браузера корректно работает с абсолютным Windows-путём через прямые слеши; после этой корректировки выбор и загрузка прошли и на минимальной странице, и в сервисе. Предыдущий непроверенный путь выбора файла закрыт успешным сквозным прогоном.

В содержимом для печати сохранены оба события и четыре кадра. Фактическая печать/сохранённый PDF по-прежнему не проверены. ## Проверка правовой справки 18 октября 2026

Выполнены **94 Python-проверки**, **29 JavaScript-проверок**, проверки сценариев установки/запуска и синтаксиса шести модулей интерфейса.
