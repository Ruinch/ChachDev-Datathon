# Экспериментальный разбор на ноутбуке

Этот режим позволяет загрузить MOV, выполнить локальный проход Qwen и получить наблюдения с исходными JPEG, временем и кандидатной нормативной ссылкой. Каждое наблюдение проверяет человек. Режим не означает, что качество модели принято для сдачи Datathon: известные ложные срабатывания и пропуски сохраняются, улучшение точности этим изменением не заявляется.

## Как пользоваться

1. Откройте [локальный сайт](http://127.0.0.1:8000/) или уже настроенный [публичный адрес](https://wadags-laptop.tail32787c.ts.net/).
2. Введите ключ отдельного профиля. На этом ноутбуке профиль находится в `C:\Users\bagwa\Documents\ForteBankDatathon\jury`, ключ — в `service.env`. Локальный файл `.local_data/laptop-profile-path.txt` хранит путь профиля без секрета. Ключ нельзя помещать в URL, JavaScript, скриншоты или отчёты. Браузер его не сохраняет.
3. После подключения убедитесь, что интерфейс сообщает об экспериментальном разборе. При включённом режиме сайт выбирает `POST /api/v1/review` автоматически.
4. Загрузите MOV и дождитесь результата. Одна задача обрабатывается за раз; конкурентная загрузка получает 429. Результат и оригинал сохраняются в журнале этого профиля.
5. Откройте исходную запись в отмеченном месте. Проверьте роли людей, направление передачи денег, принадлежность наличных и завершение операции. Кандидатная ссылка ещё не подтверждает, что все условия нормы выполнены.

Пустой список наблюдений не подтверждает отсутствие нарушений. Сообщение о недостатке контекста означает необходимость ручного просмотра. Численной вероятности правильности нет: `confidence_status: "uncalibrated"` обозначает отсутствие проверенной калибровки уверенности.

## Что возвращает API

Все запросы требуют прежний заголовок `X-API-Key`. Формат загрузки — multipart-поле `file`. Получение задачи остаётся `GET /api/v1/jobs/{job_id}`.

| Поле или маршрут | Значение |
| --- | --- |
| `/api/v1/system`: `ready` | Готовность прежнего анализа с принятыми правилами. Пока каталоги отключены, остаётся `false`. |
| `/api/v1/system`: `review.enabled` | В профиле явно включён экспериментальный режим. |
| `/api/v1/system`: `review.ready` | Доступны локальный анализатор, runtime, каталог поддерживаемых наблюдений и инструменты видео. Это техническая готовность. |
| `POST /api/v1/analyze` | Прежний контракт сохранён. С отключёнными проверенными правилами возвращает 503. |
| `POST /api/v1/review` | При готовности принимает задачу с HTTP 202 и статусом `processing`. |
| Успешный экспериментальный результат | `status: "done"`, `mode: "experimental_review"`, `review_required: true`, массив `observations`. Поля `verdict` нет. |

В `observations` сервер возвращает исходные JPEG в base64, время, текст наблюдения и `candidate_rule`. Модель не создаёт доказательные кадры и не задаёт произвольные нормативные URL. `analysis_scope` описывает фактический охват и ограничения; `full_video_checked` остаётся `false`, даже если проход по выбранным кадрам завершён. Технические сбои возвращаются как `failed` с ошибкой.

Таким образом, работающий экспериментальный сайт ещё не удовлетворяет финальному контракту жюри, требующему принятых вердиктов `violation` / `no_violation`. Для него нужны исправление качества, независимая оценка и принятие правил. Переключение режима не меняет `enabled` и `verification` в каталоге.

## Конфигурация и запуск

Существующая модель сохранена: **Qwen3.5-4B Q4_K_M**, FP16-проектор, **llama.cpp b11669 / CUDA 12.4**, alias `local-cash-vlm`, loopback `127.0.0.1:8091`. Закреплённые файлы и хеши — [model35-lock.json](../ml_tools/model35-lock.json). Настройки профиля: native video, 24 кадра, максимальная сторона 848, бюджет анализатора 210 секунд. На целевом ноутбуке используются RTX 4050 Laptop 6 ГБ и 16 ГБ RAM. Новых весов или облачного runtime этот режим не добавляет.

В `service.env` выбранного профиля режим задаёт строка:

```dotenv
APP_EXPERIMENTAL_REVIEW=true
```

После её изменения требуется перезапуск FastAPI. Не пересоздавайте профиль: в нём действующий ключ, собственная база и пути хранения. Возврат к `false` отключает новые экспериментальные загрузки после перезапуска; проверенные правила от этого не включаются.

Команды ниже выполняются из корня репозитория. Проверка локальной среды и весов без скачиваний и запуска новых серверов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-jury.ps1 -CheckOnly -InterfaceOnly -StartModel
```

Когда **оба сервиса остановлены**, фоновый запуск с журналами в закрытом профиле:

```powershell
$launcherPath = Join-Path (Get-Location) 'scripts\run-laptop.ps1'
Start-Process -FilePath "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" `
    -ArgumentList @('-NoProfile', '-ExecutionPolicy', 'Bypass', '-File', ('"{0}"' -f $launcherPath)) `
    -WorkingDirectory (Get-Location).Path -WindowStyle Hidden
```

Для ручного запуска с видимыми диагностическими сообщениями:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-jury.ps1 -InterfaceOnly -StartModel
```

Если проверенный runtime этого проекта уже работает, а **порт 8000 свободен**, запустите только API:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-jury.ps1 -InterfaceOnly
```

Здесь `-InterfaceOnly` разрешает запуск при отключённых принятых правилах; экспериментальный разбор отдельно разрешает настройка профиля. Окно ручного запуска необходимо оставить открытым. Не запускайте второй API поверх существующего. Объединённый запуск владеет созданной им моделью: остановка API через этот запускатель может остановить и runtime.

## Восстановление и доступ

Чтобы применить изменения к уже работающему основному API, владелец выполняет из корня проекта:

```powershell
.\scripts\restart-laptop.ps1
```

Если PowerShell уже открыт в папке `scripts`, команда — `.\restart-laptop.ps1`. Префикс `.\` обязателен для запуска файла из текущей папки. Сначала владелец выполняет `.\restart-laptop.ps1 -CheckOnly`: проверяются отсутствие активной задачи и оценочного процесса, владелец API и точные пути/параметры модели. Обычный перезапуск завершает API, ждёт штатного выхода runtime и при необходимости останавливает оставшийся вручную восстановленный runtime только после повторной проверки того же PID, времени создания, executable, весов, проектора, loopback-порта и alias. Затем оба сервиса запускаются заново с текущим профилем; чужие процессы не завершаются, автоматическое переиспользование модели не добавлено. Секрет не выводится; Funnel не меняется. Выполнять настоящий перезапуск должен владелец после завершения оценочных прогонов; это не проверка качества или пятиминутного лимита.

Журналы фонового запуска находятся в `logs\startup-*` внутри выбранного профиля. Проверяйте их локально; они не предназначены для публичных отчётов. При сбое сначала проверьте процессы, занимающие 8000 и 8091, и выберите подходящую команду выше. Не завершайте все процессы Python или llama.cpp на компьютере.

На этом ноутбуке обнаружено перенаправление `%LOCALAPPDATA%` внутри приложения Codex: профиль был виден агенту, но отсутствовал по тому же логическому пути в PowerShell владельца. Создан отдельный профиль в Documents с прежним ключом, настройками и отключённым каталогом; исходный профиль сохранён. Его журнал на момент переноса был пуст. Запускатели используют локальный указатель пути, поэтому больше не полагаются на перенаправленный AppData. Явный `-ProfilePath` имеет приоритет. Профиль и указатель не входят в Git.

Существующий ярлык Startup запускает `run-laptop.ps1` после входа владельца в Windows и перечитывает профиль. Автоматический контроль зависаний и работа до входа владельца не настроены. Фактический холодный старт после перезагрузки требует отдельной проверки. Подробности — [эксплуатация ноутбука](laptop-operations.md).

Funnel уже настроен: публичный HTTPS направлен только на FastAPI, порт 8000. Повторно открывать Funnel не требуется. Порт модели остаётся локальным. Для внешнего доступа нужны работающие FastAPI, Qwen, Tailscale и интернет; автономный локальный разбор не требует внешнего AI. Все зависимости и веса должны быть подготовлены заранее.

Банковский исследовательский датасет, разметка и отдельные наблюдения остаются локальными и не включаются в Git или публичные отчёты. Загруженные в кабинет оригиналы и результаты доступны владельцам общего ключа: используйте отдельный профиль для показа жюри. Коммиты и публикацию изменений выполняет владелец.

## Проверка этой интеграции

Проверено 18.10.2026:

- Полный Python-прогон: 284 теста без пропусков; после уточнения схем выполнены ещё 47 целевых проверок. После исправления пути профиля пройдены 14 проверок запускателей (10 новых и 4 существующих). JavaScript: 70 тестов без пропусков. Проверки двух эпизодов и исходных JPEG используют синтетическое видео и контролируемый тестовый анализатор, не выдаются за оценку Qwen.
- Отдельный локальный сервер на `127.0.0.1:8002` с настоящей Qwen принял синтетический бесшумный MOV и вернул `done` за 3,156 с от отправки до результата. Наблюдений 0; вердикт отсутствует, ручная проверка обязательна. Повторное получение совпало, оригинал совпал побайтово. Банковский датасет в этот тест не загружался.
- После перезапуска владельцем основной API на `127.0.0.1:8000` показал `review.ready=true`, runtime готов, строгий `ready=false`. Через настоящую Qwen повторён синтетический MOV: `done` за 3,140 с, 0 наблюдений без вердикта; исходник совпал побайтово, повторный GET идентичен. Временный сервер 8002 после проверки остановлен; его тестовые данные сохранены отдельно.
- В настоящем Edge на 8000 и временном 8002 проверены подключение, предупреждение до загрузки и открытие сохранённого результата: ошибок JavaScript нет. Пустой результат не отображается как отсутствие нарушений.
- Публичный HTTPS с ноутбука: главная 200, API без ключа 401, авторизованный system и сохранённый синтетический результат 200. Это не новая проверка из другой сети; внешнюю загрузку ещё нужно измерить отдельно.
- В приватном профиле ноутбука включён `APP_EXPERIMENTAL_REVIEW=true`, ключ и каталог правил сохранены. Рабочий профиль вынесен из перенаправленного AppData в Documents, первоначальный пустой профиль сохранён. Основной сервер успешно запущен владельцем через исправленный `restart-laptop.ps1`. Правила не включались и не объявлялись принятыми.

Оборудование этой проверки: Ryzen 5 7535HS, RTX 4050 Laptop (6141 MiB VRAM), 16 ГБ RAM (15,2 ГБ доступны ОС), драйвер NVIDIA 595.97, Python 3.12.8. Runtime и веса не заменялись: Qwen3.5-4B Q4_K_M, FP16 projector, llama.cpp b11669 CUDA 12.4, alias `local-cash-vlm`, контекст 16384, один слот, 24 видеокадра, максимум 848 px, бюджет анализатора 210 с. Lock — `ml_tools/model35-lock.json`.

Программные проверки подтверждают контракт и работу интеграции, но не точность распознавания. Последняя оценка качества и причины, по которым правила не приняты, изложены в [перепроверке ML V14](ml-quality-recheck.md). Новый внешний прогон загрузки и результата с другой сети также требует отдельного измерения.
